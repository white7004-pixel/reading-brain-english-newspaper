# 패턴 영어 허브 — 설계 문서

- 날짜: 2026-08-18
- 대상: `리브패턴퀴즈` (Reading Brain Expression Quest)
- 목표: 앱의 핵심인 **패턴 영어**(1,189표현 / 65섹션)를 메인 허브로 승격하고, 학습 실전성과 시각 품질을 함께 끌어올린다.

## 1. 문제 정의

현재 패턴 영어는 앱에서 가장 큰 콘텐츠(1,189개 표현, 65개 섹션)인데도 위계가 가장 낮다.

1. **네비게이션 부재** — 사이드바에 `동사 학습`, `북퀴즈 학습`은 전용 버튼이 있지만 패턴 영어는 전용 진입점이 없고, 65개 섹션이 `<select>` 하나에 평면으로 들어가 있다. 섹션을 찾으려면 스크롤로 훑어야 한다.
2. **진도 불능** — `markKnown()` 함수와 `.study-mark-btn` CSS는 존재하지만 카드 화면에 버튼이 없다. 결과적으로 카드 학습만으로는 `mastered`가 절대 늘지 않고, 대시보드 진도율은 사실상 0%에 고정된다.
3. **섹션 단위 피드백 없음** — 진도는 전체 1,189개 기준 하나뿐이라, "이 섹션을 얼마나 끝냈는지"를 학생도 교사도 알 수 없다.
4. **이어하기 없음** — 새로고침하면 항상 첫 섹션 첫 카드로 돌아간다.
5. **시각 위계 평면적** — 모드바는 단순 버튼 6개, 카드에는 섹션 진행 맥락이 없다.

## 2. 설계 원칙

- 기존 학습 로직(퀴즈/매칭/블래스트/복습/랭킹)은 건드리지 않는다. 진입 경로와 표현만 바꾼다.
- 진도는 **저장하지 않고 파생 계산**한다. 이미 있는 `state.mastered`(표현 id 집합)와 섹션 정보로 전부 계산 가능하므로 새 저장 스키마를 만들지 않는다.
- 순수 계산은 DOM과 분리해 별도 모듈에 두고 노드 테스트로 검증한다.

## 3. 컴포넌트

### 3.1 `pattern-hub-model.js` (신규, 순수 모듈)

`learning-dashboard-model.js`와 같은 UMD 패턴. DOM 의존 없음.

| 함수 | 입력 | 출력 |
|---|---|---|
| `parseSectionName(category)` | `"05. He / She / It is 패턴"` | `{ number: 5, title: "He / She / It is 패턴", group: "basic" }` |
| `buildSections(expressions, masteredIds)` | 표현 배열 + 마스터 id 집합/배열 | 섹션 배열 `{ key, number, title, group, total, mastered, percent, status }` |
| `groupSections(sections)` | 섹션 배열 | `[{ id, label, sections, total, mastered, percent }]` |
| `filterSections(sections, query)` | 섹션 배열 + 검색어 | 매칭 섹션 배열 |
| `findNextSection(sections, key)` | 섹션 배열 + 현재 키 | 다음 섹션 또는 `null` |
| `summarizeDaily(daily, goal)` | 오늘 기록 + 목표 | `{ cards, correct, percent, done }` |

그룹 규칙: 카테고리명이 `Training 800`을 포함하면 `training`, 그 외는 `basic`.
상태 규칙: `percent === 0` → `new`, `percent === 100` → `done`, 그 외 `learning`.

### 3.2 패턴 네비게이터 (사이드바)

- 최상단 `PATTERN ENGLISH` 1급 섹션. 동사/북퀴즈는 그 아래 보조 섹션.
- 구성: 허브 바로가기 버튼 → 검색 입력 → 그룹 아코디언(`기초 패턴` / `Training 800`) → 섹션 행 목록.
- 섹션 행: 번호 배지 + 제목 + 미니 진도바 + `n/N`.
- 기존 `#categorySelect`는 **DOM에 숨겨진 채 유지**하고 네비게이터가 값을 동기화한다. 퀴즈·카드 이동 등 기존 코드가 이 엘리먼트를 참조하므로 제거하지 않는다.
- 검색어가 있으면 아코디언은 자동으로 펼쳐 매칭 결과만 보여준다.

### 3.3 패턴 허브 화면 (`#hubView`, 신규 뷰)

모드바에 `허브` 버튼을 추가하고, 로그인 직후 기본 화면으로 삼는다.

1. **이어하기 배너** — 마지막 섹션/카드 위치와 해당 섹션 진도율. 클릭 시 카드 학습으로 복귀.
2. **오늘의 목표** — 오늘 넘긴 카드 수와 정답 수를 목표(카드 20 / 정답 10) 대비 링으로 표시.
3. **그룹 탭 + 검색** — 네비게이터 검색어와 동일한 상태를 공유.
4. **섹션 카드 그리드** — 섹션별 진도 링, 마스터/전체, 상태 뱃지(`시작 전`/`학습 중`/`완료`). 클릭 시 해당 섹션 카드 학습으로 진입.

### 3.4 학습 실전성

- **`알아요 / 헷갈려요` 버튼 복원** — 카드 학습 화면에서 `markKnown(true|false)` 호출. 진도가 실제로 증가하는 유일한 경로.
- **이어하기 저장** — `rb-last-position` = `{ category, index }`, 카드 렌더마다 갱신.
- **오늘 학습량** — `rb-daily` = `{ date, cards, correct }`. 날짜가 바뀌면 리셋.
- **섹션 완주 배너** — 현재 섹션 100% 도달 시 카드 화면 상단에 다음 섹션 이동 배너.
- **키보드 단축키** — `←`/`→` 카드 이동, `Space`/`Enter` 뒤집기, `S` 발음, `1`/`2` 알아요/헷갈려요. 입력 요소에 포커스가 있으면 무시.

### 3.5 비주얼

- 디자인 토큰 보강(반경·그림자·그라디언트), 모드바를 세그먼트 컨트롤로 교체.
- 플래시카드에 섹션 칩 + 섹션 진도바 추가, 타이포 스케일 정리.
- 네비게이터 hover/active(골드 레일) 상태, 1100px 이하 반응형 정리.

## 4. 데이터 흐름

```
expressions(정적) ─┐
                   ├─ buildSections() ─ sections ─┬─ 사이드바 네비게이터
state.mastered  ───┘                              ├─ 허브 섹션 그리드
                                                  ├─ 카드 화면 섹션 진도바
                                                  └─ 다음 섹션 제안
```

섹션 클릭 → `state.category` 갱신 + `#categorySelect.value` 동기화 → `setMode("study")` (기존 경로 그대로).

## 5. 오류 처리

- 카테고리명이 `NN. ` 형식을 벗어나면 `number: null`로 두고 원문을 제목으로 사용, 그룹은 `basic`으로 처리한다.
- `localStorage`의 `rb-last-position` / `rb-daily`가 손상되면 조용히 기본값으로 되돌린다.
- 저장된 마지막 섹션이 현재 데이터에 없으면 이어하기 배너를 숨긴다.
