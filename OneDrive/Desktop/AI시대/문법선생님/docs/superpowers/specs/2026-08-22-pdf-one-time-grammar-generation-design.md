# PDF 1회 생성형 문법 AI 선생님 설계

## 목표

제공된 천일문 중등 GRAMMAR 1·2·3 PDF를 빌드 시 한 번 분석하여 98개 단원의 강의 콘텐츠와 단원별 맞춤 이미지 98장을 생성하고, 결과물을 현재 정적 앱에 저장한다. 학생이 앱을 사용할 때는 AI API나 인터넷 연결이 필요하지 않아야 한다.

## 입력 범위

초기 생성은 다음 세 파일만 대상으로 한다.

- `C:\Users\white\Downloads\천일문그래머_1권.pdf`
- `C:\Users\white\Downloads\천일문그래머_2권_본문(학생용).pdf`
- `C:\Users\white\Downloads\천일문 중등 그래머_3권_본문.pdf`

향후 새 PDF를 추가할 때는 같은 생성 명령을 다시 실행할 수 있지만, 학생용 화면에는 PDF 업로드나 API 키 입력 기능을 노출하지 않는다.

## 핵심 원칙

- PDF에서는 목차, 단원명, 문법 범위, 페이지 참조만 추출한다.
- 교재 본문, 예문, 문제를 그대로 복제하지 않는다.
- 설명, 비유, 예문, 함정, 기억법, 퀴즈는 새로 생성한다.
- 생성 결과는 검수 가능한 중간 산출물로 먼저 저장하고 승인된 결과만 앱에 반영한다.
- 단원별 생성은 기본적으로 한 번만 수행하며, 입력 해시와 생성 상태로 중복 호출을 방지한다.
- 학생 실행 시에는 외부 API 호출이 없어야 한다.

## 전체 흐름

1. PDF 세 파일의 존재 여부와 SHA-256 해시를 기록한다.
2. PDF에서 페이지별 텍스트와 목차 후보를 추출한다.
3. 추출 결과를 현재 `ALL_UNITS`의 98개 단원과 대조한다.
4. 단원별 생성 명세를 만든다: 제목, 문법 목표, 페이지 참조, 난이도, 이미지 장면 요약.
5. AI가 단원별 강의 콘텐츠 초안을 생성한다.
6. 스키마 검사와 중복·저작권 안전 검사를 수행한다.
7. 각 단원의 강의 내용과 대표 예문에 맞춘 이미지 프롬프트를 생성한다.
8. 단원별 16:9 이미지를 한 번 생성하여 로컬에 저장한다.
9. 이미지 파일, 대체 텍스트, 단원 ID를 연결한다.
10. 자동 테스트와 시각 검토를 통과한 결과를 정적 앱에 반영한다.

## 콘텐츠 생성 계약

각 단원은 현재 앱과 호환되는 다음 필드를 유지한다.

- `id`, `book`, `chapter`, `title`, `pageReference`
- `hook`: 핵심을 한 문장으로 설명
- `analogy`: 중학생이 이해할 생활 비유
- `formula`: 문법 구조 공식
- `examples`: 고유 영어 예문, 한국어 해석, 형태 초점 최소 2개
- `trap`: 대표 오답, 정답, 틀린 이유
- `memory`: 기억 공식
- `quiz`: 보기, 정답, 해설이 있는 최소 3문제
- `visualId`: 단원별 이미지 식별자

모든 영어 예문은 단원 간 중복을 허용하지 않는다. 정답 인덱스, 필수 필드, 단원 ID 집합은 기존 도메인 검사를 통과해야 한다.

## 단원별 이미지 설계

기존 12개 공통 문법군 이미지를 98개 단원별 이미지로 교체한다. 각 이미지는 해당 단원의 `hook`, `analogy`, 첫 번째 대표 예문을 바탕으로 장면을 구성한다.

공통 시각 규칙은 다음과 같다.

- 한국 중학생의 실제 생활과 학습 장면
- 고급 교육 광고 수준의 자연스러운 실사 스타일
- 네이비와 샴페인 골드가 은은하게 연결되는 색감
- 16:9 가로 구성, 주요 피사체가 중앙에서 벗어나지 않음
- 이미지 안 글자, 로고, 워터마크 없음
- 손가락, 얼굴, 교실 소품 왜곡 최소화
- 문법 개념을 추상 기호보다 실제 행동과 상황으로 표현

예를 들어 `be동사의 긍정문`은 정지한 학생과 달리는 학생의 일반 대비가 아니라, 첫 예문의 상태가 실제로 드러나는 장면을 사용한다. `셀 수 있는 명사와 셀 수 없는 명사`는 개수로 나누는 사물과 양으로 재는 재료를 한 생활 장면 안에서 비교한다.

이미지는 `assets/lesson-visuals/<unit-id>.png`에 저장하며, 레지스트리는 단원 ID를 직접 키로 사용한다. 기존 12개 이미지는 호환용 폴백으로 남긴다.

## 1회 생성과 재실행 방지

`generated/manifest.json`에 다음 정보를 기록한다.

- PDF 경로와 해시
- 생성기 버전
- 단원별 콘텐츠 상태와 이미지 상태
- 사용한 프롬프트 해시
- 생성 시각과 검수 상태

입력 해시와 프롬프트 해시가 같고 산출물이 존재하면 해당 단원은 건너뛴다. `--force <unit-id>`를 지정했을 때만 특정 단원을 다시 생성한다. 전체 강제 재생성은 별도의 명시적 옵션으로만 허용한다.

## 파일 구조

- `scripts/extract_pdf_outline.py`: PDF 텍스트·목차 추출 확장
- `scripts/build_generation_specs.mjs`: PDF 결과와 98개 단원 대조
- `scripts/generate_lessons.mjs`: 단원별 콘텐츠 생성 및 스키마 저장
- `scripts/generate_lesson_images.mjs`: 승인된 단원별 이미지 생성
- `generated/outlines/`: PDF별 추출 결과
- `generated/specs/`: 단원별 생성 명세
- `generated/drafts/`: 검수 전 콘텐츠 초안
- `generated/manifest.json`: 해시와 생성 상태
- `assets/lesson-visuals/`: 최종 단원별 이미지
- `js/content/`: 승인된 최종 강의 데이터
- `js/visuals.js`: 단원 ID 기반 최종 이미지 레지스트리와 폴백

## 오류 처리

- PDF 누락 또는 해시 변경: 생성 전 중단하고 대상 파일을 명확히 표시한다.
- 목차와 98개 단원 불일치: 자동 생성하지 않고 불일치 보고서를 만든다.
- AI 응답 형식 오류: 해당 단원만 제한 횟수 내 재시도하고 나머지 상태는 보존한다.
- 이미지 생성 실패: 기존 문법군 이미지를 임시 폴백으로 유지하고 미완료 상태로 기록한다.
- 생성 중 중단: 완료된 단원은 유지하고 다음 실행에서 미완료 단원만 계속한다.
- 품질 검사 실패: 자동으로 앱에 반영하지 않고 검수 대기 상태로 둔다.

## 비용과 보안

- API 키는 로컬 환경 변수 또는 서버 전용 설정에서만 읽고 Git과 브라우저 코드에 저장하지 않는다.
- PDF와 생성 초안은 외부 공개 저장소에 업로드하지 않는다.
- 생성 전 예상 호출 수를 표시한다.
- 기본 실행은 콘텐츠 98회와 이미지 98회의 최대 호출을 허용하되 완료 단원은 재호출하지 않는다.
- 실제 제공자가 배치 입력을 지원하면 동일한 검증 계약을 유지하면서 배치 처리할 수 있다.

## 검증

- PDF 세 파일의 해시와 페이지 수가 기록되는지 검사한다.
- 추출된 단원 ID가 `ALL_UNITS` 98개와 정확히 일치하는지 검사한다.
- 모든 콘텐츠가 기존 `validateLesson` 계약을 통과하는지 검사한다.
- 영어 예문과 문제 문구의 비정상 중복을 검사한다.
- 모든 단원 ID가 고유 이미지 파일과 구체적인 한국어 대체 텍스트를 갖는지 검사한다.
- 이미지가 16:9에 가까운 비율이고 최소 해상도·파일 크기를 충족하는지 검사한다.
- 콘텐츠·이미지 생성이 완료된 상태에서 재실행 시 API 호출이 0회인지 검사한다.
- 1·2·3권 대표 단원을 모바일·태블릿·데스크톱에서 열어 이미지와 강의 내용의 일치를 시각 확인한다.
- 기존 퀴즈, 진도 저장, 음성, 녹음, 인쇄 회귀 테스트를 유지한다.

## 완료 기준

- 98개 단원이 각각 고유한 강의 내용과 고유 이미지를 가진다.
- 이미지 장면이 단원 제목, 핵심 설명, 대표 예문 중 적어도 두 요소와 직접 대응한다.
- 제공된 PDF 세 파일은 생성 후 다시 필요하지 않으며 앱은 완전한 로컬 정적 실행을 유지한다.
- 동일 입력으로 생성 파이프라인을 다시 실행해도 완료된 콘텐츠와 이미지에 대한 추가 AI 호출이 발생하지 않는다.
- 새 PDF를 추가할 때 같은 파이프라인을 재사용할 수 있다.
