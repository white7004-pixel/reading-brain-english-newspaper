# 읽기 후 핵심 찾기·읽기 속도·맵 콘텐츠 확장 설계

## 목표

기존 논픽션 리딩랩의 기능과 콘텐츠를 보존하면서 학습 흐름을 `본문 읽기 → 읽기 결과 → 핵심 찾기 → 이해 퀴즈 → 완료` 순서로 바꾼다. 실제 읽기 시간을 기록해 분당 문자 수를 계산하고, 2,000자/분 이상인 경우 학습자에게 옐로우카드를 보여준다. 기존 다섯 지식 퀘스트 맵은 각 다섯 콘텐츠로 확장한다.

## 학습 흐름

1. 학습자가 본문 읽기를 시작하면 활성 읽기 시간이 누적된다.
2. 모든 본문 페이지를 읽기 전에는 핵심단어·핵심문장 찾기를 노출하지 않는다.
3. 마지막 페이지를 완료하면 읽기 결과 화면에서 총 읽기 시간, 전체 문자 수, 분당 문자 수를 보여준다.
4. 분당 문자 수가 2,000 이상이면 옐로우카드와 천천히 다시 읽기 동작을 제공한다.
5. 학습자는 결과 확인 후 핵심 찾기를 수행하고 이해 퀴즈로 이동한다.
6. 퀴즈 완료 시 읽기 측정값과 핵심 찾기 결과를 기존 학습 시도 기록에 함께 저장한다.

## 읽기 시간과 속도 계산

- 본문 첫 화면이 표시된 시점부터 마지막 페이지 완료 시점까지 측정한다.
- 문서가 보이지 않거나 브라우저 탭이 비활성화된 동안은 시간을 누적하지 않는다.
- 페이지 이동 중에도 읽기 화면이 활성 상태라면 시간을 계속 누적한다.
- 오디오 재생 시간도 학습자가 본문 화면을 보고 있으면 읽기 시간에 포함한다.
- 다시 읽기를 선택하면 해당 읽기 세션의 시간과 판정을 초기화한다.
- 전체 문자 수는 모든 본문 페이지 문자열의 길이 합계다. 알파벳, 공백, 문장부호를 모두 포함한다. 페이지 배열을 연결하며 새 문자를 추가하지 않는다.
- 분당 문자 수는 `전체 문자 수 / (활성 읽기 밀리초 / 60,000)`으로 계산하고 화면에는 반올림한 정수로 표시한다.
- 2,000자/분 이상이면 옐로우카드다. 2,000 미만은 정상 판정이다.
- 1초 미만의 비정상적으로 짧은 측정도 계산 가능하도록 분모는 최소 1초로 제한한다.

## 화면 구성

### 본문 읽기

- 현재 핵심 찾기 토글과 선택 UI를 본문 화면에서 제거한다.
- 기존 어휘 도움, 원어민 오디오, 페이지 진행, 출처 정보는 유지한다.
- 마지막 버튼은 읽기 결과로 이동한다.

### 읽기 결과

- 총 읽기 시간, 전체 문자 수, 분당 문자 수를 명확한 카드로 표시한다.
- 정상 판정이면 핵심 찾기로 이동하는 주 동작을 제공한다.
- 옐로우카드이면 경고 이유와 기준을 알려주고 `천천히 다시 읽기`, `핵심 찾기 계속하기`를 모두 제공한다. 경고는 학습을 차단하지 않는다.

### 핵심 찾기

- 완독한 전체 본문을 대상으로 핵심단어와 핵심문장을 선택한다.
- 기존 정답 확인, 보상 계산, 이벤트 기록 방식은 유지한다.
- 정답을 확인한 뒤 이해 퀴즈로 이동한다.

### 성장 기록

- 학습 시도에 읽기 시간, 전체 문자 수, 분당 문자 수, 옐로우카드 여부를 저장한다.
- 기존 기록을 읽을 수 있도록 새 필드는 선택값으로 추가하고, 과거 기록에는 안전한 기본 표시를 사용한다.
- 성장 리포트에서 최근 읽기 속도와 총 읽기 시간을 확인할 수 있게 한다.

## 구성 요소와 데이터 경계

- 읽기 시간 측정과 속도 계산은 순수 계산 모듈로 분리한다.
- `ReaderScreen`은 본문 읽기와 활성 시간 보고만 담당한다.
- 읽기 결과와 핵심 찾기는 독립 화면 구성 요소로 분리한다.
- `LearnerApp` 세션 상태가 `reader`, `reading-result`, `key-finder`, `quiz`, `completion` 단계를 조정한다.
- 저장 모델은 기존 필드를 유지하고 읽기 지표만 확장한다.

## 맵별 콘텐츠 확장

기존 공개 콘텐츠와 연결 관계는 수정하거나 삭제하지 않는다. 다섯 컬렉션을 각각 다섯 콘텐츠로 맞춰 총 25개로 확장한다.

| 맵 | 현재 | 추가 | 완료 후 |
|---|---:|---:|---:|
| 과학 관찰자 | 3 | 2 | 5 |
| 역사 메이커 | 3 | 2 | 5 |
| 만들어지는 예술 | 3 | 2 | 5 |
| 생각하는 행동 | 4 | 1 | 5 |
| 움직이는 문화 | 2 | 3 | 5 |

추가 콘텐츠는 기존 AR1 난이도, 문장 길이, 어휘·퀴즈·핵심문장·출처·검토 메타데이터 규칙을 따른다. 각 맵의 기존 마지막 노드 뒤에 순차 연결하며 다른 맵의 잠금 조건은 바꾸지 않는다. 콘텐츠는 스튜디오의 검토·게시 경계를 통과한 기존 시드 방식으로 추가한다.

## 오류와 복구

- 탭 가시성 이벤트가 지원되지 않아도 화면 활성 시간 기준으로 기본 측정이 동작한다.
- 저장된 과거 학습 기록에 새 지표가 없어도 앱이 중단되지 않는다.
- 읽기 도중 나갔다가 재개하면 기존 퀘스트 페이지 복원 동작은 유지한다. 새 읽기 측정은 재개 시점부터 시작하며 완료 기록에는 이번 활성 세션 시간을 사용한다.
- 옐로우카드는 안내이며 퀴즈 진입이나 완료를 차단하지 않는다.

## 테스트와 검증

- 순수 계산 테스트: 공백·문장부호 포함 문자 수, 활성 시간, 2,000 경계값, 반올림.
- 구성 요소 테스트: 완독 전 핵심 찾기 미노출, 읽기 결과 표시, 옐로우카드, 다시 읽기, 핵심 찾기 이후 퀴즈 이동.
- 저장 테스트: 새 기록 저장과 구버전 기록 호환.
- 콘텐츠 테스트: 맵별 다섯 개, 총 25개, 순서·선행·다음 연결, AR1 품질 규칙.
- 전체 Vitest, TypeScript 검사, Next.js 프로덕션 빌드, Playwright 학습 흐름을 실행한다.
- 개발 서버에서 모바일과 데스크톱 화면을 열어 결과 화면과 핵심 찾기 순서를 확인한다.

## 범위 밖

- 서버 계정 동기화, 교사 대시보드, 읽기 속도에 따른 자동 레벨 변경은 이번 작업에 포함하지 않는다.
- 2,000자/분 기준을 연령이나 AR 단계별로 다르게 적용하지 않는다.
