# 몽글 통합 집중·메시지 설계

## 1. 제품 방향

몽글은 중학생부터 성인까지를 위한 ADHD 친화형 실행 도우미다. 사용자가 해야 할 일과 답장할 메시지를 한곳에 모으고, 복잡한 계획을 지금 시작할 수 있는 하나의 행동으로 바꾼다.

제품의 두 축은 동등하게 중요하다.

1. 집중과 할 일 관리
2. 메시지 예약과 메시지에서 할 일 만들기

두 축을 별도 앱처럼 분리하지 않는다. 메시지를 가져오면 답장 예약, 할 일 저장 또는 두 가지를 동시에 선택할 수 있고, 생성된 항목은 오늘의 흐름과 집중 실행 화면으로 연결된다.

## 2. 대상 사용자

- 중학생: 과제, 시험, 학원, 생활 루틴 관리
- 고등학생: 학습 계획, 수행평가, 입시 일정, 메시지 답장 관리
- 대학생: 수업, 과제, 팀 프로젝트, 취업 준비 관리
- 직장인과 성인: 업무, 회의, 생활 루틴, 메시지 예약 관리

연령에 따라 화면 구조를 바꾸지 않는다. 가입 시 선택한 사용자 유형에 따라 예시 문구, 추천 루틴, 기본 분류와 우선 노출 콘텐츠만 달라진다.

## 3. 설계 원칙

### 3.1 지금 하나만

홈 화면은 전체 미완료 개수보다 지금 해야 할 행동 하나를 가장 크게 보여준다. 사용자는 시작, 완료, 10분 미루기 중 하나를 즉시 선택할 수 있다.

### 3.2 안정된 화면

테마, 캐릭터 또는 연령 설정이 바뀌어도 정보 구조, 버튼 위치와 화면 골격은 유지한다. 사용자가 선택한 테마와 밝기 모드는 저장하며, 자동 밝기 전환은 명시적으로 선택한 경우에만 사용한다.

### 3.3 낮은 인지 부하

- 화면마다 주 행동은 하나만 강조한다.
- 추가 설정은 점진적으로 펼쳐 보인다.
- 한 화면의 강조색은 하나만 사용한다.
- 캐릭터와 애니메이션은 정보나 조작부를 가리지 않는다.
- 죄책감, 벌점, 연속 기록 초기화로 사용자를 압박하지 않는다.

### 3.4 실패해도 다시 시작

미완료 항목에는 포기 대신 축소, 연기, 재배치 옵션을 제공한다. 보상은 완료뿐 아니라 시작, 복귀, 일정 시간 진행에도 제공한다.

## 4. 정보 구조

하단 탭은 다음 다섯 개로 고정한다.

1. 오늘
2. 집중
3. 메시지
4. 루틴
5. 설정

### 4.1 오늘

오늘 화면은 세 영역으로 구성한다.

1. 빠른 캡처
   - 할 일 입력
   - 메시지 붙여넣기 또는 공유로 가져오기
   - 답장 예약
2. 지금 하나만
   - 현재 행동
   - 예상 시간
   - 시작, 완료, 10분 미루기
3. 오늘의 흐름
   - 할 일, 수업·일정, 발송 예정 메시지를 하나의 시간순 타임라인으로 표시

### 4.2 집중

- 현재 행동 하나와 남은 시간을 크게 표시한다.
- 시작, 일시정지, 완료, 시간 추가를 제공한다.
- 큰 작업은 AI가 작은 체크리스트로 나눈다.
- 완료 후 예상 시간과 실제 시간을 비교해 다음 예상치를 개선한다.

### 4.3 메시지

- 플랫폼별 받은 메시지 또는 붙여넣은 메시지를 모아 보여준다.
- 작성 중, 예약됨, 발송됨, 실패 상태를 구분한다.
- 예약 항목은 수정, 즉시 발송, 취소할 수 있다.
- 메시지를 할 일로 전환하거나 답장 예약과 할 일 생성을 동시에 수행할 수 있다.

지원 대상은 카카오톡, 카카오워크, Slack, Telegram이다.

### 4.4 루틴

- 아침 준비, 공부 시작, 퇴근 정리 등 여러 단계를 순서대로 실행한다.
- 단계별 타이머, 음성 안내, 건너뛰기와 시간 추가를 제공한다.
- 루틴 종료 예상 시각을 항상 보여준다.

### 4.5 설정

- 사용자 유형과 콘텐츠 추천
- 알림 강도와 방해금지 시간
- 플랫폼 연결과 권한 상태
- 밝기와 색상 테마
- 캐릭터 선택과 움직임 줄이기
- 데이터 내보내기와 계정 관리

## 5. 핵심 사용자 흐름

### 5.1 생각을 행동으로 바꾸기

1. 사용자가 빠른 캡처에 생각을 자유롭게 입력한다.
2. 몽글이 할 일, 예상 시간, 기한과 작은 실행 단계로 정리한다.
3. 불확실한 날짜나 대상은 저장 전에 사용자가 확인한다.
4. 저장된 항목은 오늘의 흐름에 배치된다.
5. 실행 시 집중 화면이 열린다.

### 5.2 메시지 처리

1. 사용자가 메시지를 공유하거나 붙여넣는다.
2. 몽글이 발신자, 요청 내용, 기한 표현과 답장 필요 여부를 제안한다.
3. 사용자는 다음 중 하나를 선택한다.
   - 답장 예약
   - 할 일로 저장
   - 답장 예약과 할 일 동시 생성
4. 예약 메시지는 오늘의 흐름과 메시지 탭에 동시에 표시된다.
5. 발송 결과는 성공 또는 실패로 기록되고 실패 시 재시도 또는 직접 보내기를 안내한다.

### 5.3 계획 붕괴 구조대

사용자가 일정이 밀렸음을 표시하면 남은 항목마다 다음 선택을 제공한다.

- 오늘 꼭 하기
- 내일로 이동
- 5분 버전으로 축소
- 취소해도 됨

변경 결과와 새 종료 예상 시각을 확인한 후 한 번에 적용한다.

## 6. 플랫폼별 메시지 정책

### 6.1 Slack

- 공식 예약 메시지 API를 사용한다.
- 연결된 계정과 앱이 접근할 수 있는 DM, 공개 채널 및 비공개 채널만 대상으로 제공한다.
- 플랫폼 제한과 권한 오류를 예약 시점에 먼저 검사한다.

### 6.2 Telegram

- 개인 대화, 그룹과 채널을 지원한다.
- 초기 버전은 봇 기반 발송을 기본으로 하며 메시지가 봇 이름으로 전송됨을 명확히 표시한다.
- 사용자 계정 기반 발송은 인증정보 보호와 별도 보안 검토 없이는 제공하지 않는다.

### 6.3 카카오워크

- 공식 Bot API를 사용한다.
- Bot이 참여하고 권한을 가진 1:1 대화와 채팅방을 지원한다.
- 예약 시각에 몽글 서버가 발송 API를 호출한다.

### 6.4 카카오톡

- 공식 API가 허용하는 같은 서비스 사용자, 동의한 친구와 승인된 메시지 형식만 자동 발송한다.
- 일반 대화방 또는 권한이 없는 대상은 예약 시각에 작성된 내용을 열고 사용자가 최종 전송하도록 안내한다.
- 접근성 자동화, 화면 매크로 또는 비공식 API는 사용하지 않는다.

## 7. 예약 발송 시스템

예약 항목은 플랫폼, 대화 대상, 본문, 예약 시각, 시간대, 발송 방식, 상태와 재시도 횟수를 가진다. 상태는 `draft`, `scheduled`, `sending`, `sent`, `failed`, `canceled`, `manual_action_required`로 관리한다.

- 서버는 시간대가 포함된 절대 시각으로 예약을 저장한다.
- 같은 예약의 중복 발송을 막는 고유 키를 사용한다.
- 일시적인 네트워크 오류만 제한적으로 재시도한다.
- 인증 만료나 권한 부족은 재시도하지 않고 연결 갱신을 요청한다.
- 발송 전 수정과 취소가 가능해야 한다.
- 발송과 상태 변경 기록을 사용자가 확인할 수 있어야 한다.

## 8. 시각 디자인

### 8.1 방향

성인이 직장에서도 사용할 수 있으면서 학생에게 차갑지 않은 차분한 캐릭터형 생산성 UI를 사용한다.

- 중성적인 밝은 배경과 한 가지 라벤더 계열 강조색을 기본으로 한다.
- 모서리가 부드러운 카드와 명확한 타이포그래피를 사용한다.
- 캐릭터는 조언, 시작 신호와 완료 축하에만 등장한다.
- 장식용 그라데이션과 동시에 움직이는 요소를 최소화한다.
- 색상만으로 상태를 구분하지 않고 아이콘과 텍스트를 함께 사용한다.

### 8.2 고정 디자인 기준

- 홈의 주 행동 버튼은 항상 같은 위치에 둔다.
- 하단 탭의 순서와 아이콘을 고정한다.
- 카드 간격, 모서리 반경과 제목 크기를 디자인 토큰으로 관리한다.
- 테마 변경은 색상 토큰만 바꾸며 레이아웃을 변경하지 않는다.
- 캐릭터의 무작위 이동을 제거한다.
- 움직임 줄이기 설정에서는 장식 애니메이션을 모두 정지한다.

### 8.3 문구

- `12개 남았어요`보다 `지금 이것부터 해볼까요?`를 우선한다.
- `실패`보다 `다시 예약하기` 또는 `직접 보내기 필요`처럼 다음 행동을 말한다.
- 학습용 문구와 업무용 문구는 사용자 유형에 맞추되 버튼 이름은 동일하게 유지한다.

## 9. 접근성과 안전

- 본문과 버튼은 WCAG AA 수준의 명도 대비를 목표로 한다.
- 동작 영역은 모바일에서 최소 44×44 포인트로 제공한다.
- 글자 크기 확대 시 핵심 조작이 잘리지 않아야 한다.
- 알림 빈도와 조용한 시간을 사용자가 직접 설정한다.
- 플랫폼 토큰은 클라이언트에 평문으로 저장하지 않는다.
- 메시지 본문과 수신자는 민감정보로 취급하며 필요한 기간만 저장한다.
- 발송 전 미리보기에서 플랫폼, 대상과 시각을 한 화면에 보여준다.

## 10. 첫 출시 범위

첫 출시의 핵심 기능은 다음 다섯 가지다.

1. 브레인 덤프에서 할 일 만들기
2. 지금 하나만 실행 화면
3. AI 작업 쪼개기와 예상 시간
4. 시각적 집중 타이머
5. 메시지 예약과 메시지에서 할 일 만들기

루틴 실행은 기본 단계 타이머까지 포함한다. 바디 더블링, 공개 커뮤니티, 고급 통계와 사용자 계정 기반 Telegram 발송은 후속 범위로 둔다.

## 11. 성공 기준

- 신규 사용자가 2분 안에 첫 할 일 또는 예약 메시지를 만들 수 있다.
- 홈에서 두 번 이하의 조작으로 집중 타이머를 시작할 수 있다.
- 공유하거나 붙여넣은 메시지를 세 번 이하의 조작으로 할 일 또는 예약 답장으로 저장할 수 있다.
- 예약 목록에서 발송 대상, 시각과 상태를 즉시 구분할 수 있다.
- 연령 유형, 테마와 캐릭터를 변경해도 주요 화면 구조가 유지된다.
- 네트워크 오류나 권한 만료가 발생해도 중복 메시지를 보내지 않는다.

## 12. 검증

- 중학생, 고등학생, 대학생과 직장인 사용자 유형별 핵심 흐름 사용성 테스트
- 밝은 화면, 어두운 화면, 큰 글자와 움직임 줄이기 시각 회귀 테스트
- 각 플랫폼의 성공, 권한 부족, 인증 만료, 네트워크 오류와 중복 요청 테스트
- 예약 생성, 수정, 취소, 즉시 발송과 수동 전송 전환 테스트
- 시간대 변경과 일광절약시간 경계 테스트
