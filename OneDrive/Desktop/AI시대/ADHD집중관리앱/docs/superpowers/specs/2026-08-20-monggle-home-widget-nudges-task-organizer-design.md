# 몽글 홈 위젯·잔소리·오늘 할 일 정리 설계

## 목표

사용자가 자연어로 오늘 할 일을 한 번에 입력하면 기기 안에서 구조화된 목록으로 정리하고, 확인·수정 후 저장할 수 있게 한다. 저장된 오늘 할 일과 몽글의 짧은 안내 문구는 Android와 iOS 홈 화면 위젯에 표시한다. 사용자가 선택한 간격에 따라 홈 위젯 말풍선과 휴대폰 알림으로 다음 행동을 안내한다.

## 제품 원칙

- 중·고등학생부터 성인까지 부담 없이 이해할 수 있는 표현을 사용한다.
- 잔소리는 비난·압박이 아니라 지금 할 수 있는 가장 작은 행동을 알려준다.
- 자동 분석 결과는 저장 전에 사용자가 확인하고 수정한다.
- 외부 유료 AI나 사용량 기반 크레딧을 사용하지 않는다.
- 할 일 문장과 분석 결과는 기본적으로 기기 밖으로 전송하지 않는다.
- 기존 PWA와 Studio 3D 보라 디자인, 기본 몽글 캐릭터를 유지한다.

## 기술 접근

기존 React PWA를 Capacitor로 Android와 iOS 앱에 포함한다. 공통 화면과 할 일 로직은 현재 TypeScript 코드를 사용하고, 홈 위젯과 예약 알림만 운영체제별 네이티브 기능으로 구현한다.

- 공통 앱: React, TypeScript, Dexie 기반 할 일·설정 관리
- 모바일 셸: Capacitor
- Android 위젯: AppWidgetProvider 및 WorkManager
- iOS 위젯: WidgetKit 및 AppIntent
- 네이티브 연결: Capacitor 플러그인 인터페이스
- 로컬 분석: 규칙 기반 한국어 파서와 결정적 우선순위·시간 추출

React Native 전면 재개발이나 플랫폼별 앱 이중 개발은 기존 기능 재사용률이 낮고 유지 비용이 커서 이번 범위에서 제외한다.

## 자연어 할 일 정리

### 입력 예시

`오늘 영어 단어 30개 외우고 3시에 병원 갔다가 저녁에 엄마에게 문자`

### 출력 초안

1. 영어 단어 30개 외우기 — 오늘, 시간 미정, 예상 30분
2. 병원 방문 — 오늘 오후 3시
3. 엄마에게 문자 — 오늘 저녁, 병원 방문 이후

### 처리 규칙

- 쉼표, 줄바꿈, 접속 표현(`하고`, `그리고`, `갔다가`, `후에`)을 작업 경계 후보로 사용한다.
- `오늘`, `내일`, 요일, 오전·오후, 숫자 시각을 날짜와 시간으로 변환한다.
- `먼저`, `후에`, `갔다가`로 순서 관계를 추출한다.
- 숫자와 단위가 있는 학습 작업은 보수적인 예상 시간을 제안한다.
- 인식이 불확실한 필드는 `확인 필요`로 표시하고 임의로 확정하지 않는다.
- 분석만으로 저장하지 않는다. 사용자가 제목, 날짜, 시간, 중요도, 예상 시간을 확인한 후 `모두 저장`을 눌러야 한다.

첫 버전은 외부 모델을 사용하지 않는 결정적 파서로 제공한다. 향후 기기 내 언어 모델을 추가하더라도 동일한 초안 인터페이스를 사용하며, 사용자의 명시적 선택 없이 네트워크 분석으로 전환하지 않는다.

## 잔소리 설정과 동작

사용자는 설정에서 `끄기`, `30분마다`, `1시간마다`, `2시간마다`를 선택한다. 기본값은 `1시간마다`이다.

알림 시점에는 완료되지 않은 오늘 할 일 중 다음 한 항목을 선택한다. 기한이 있는 항목, 이미 시작한 항목, 우선순위가 높은 항목 순으로 고른다. 문구는 다음 행동 하나만 포함한다.

- 시작 전: `몽글: 수학 숙제, 문제 한 개만 먼저 열어볼까?`
- 진행 중: `몽글: 10분만 이어가면 흐름을 지킬 수 있어.`
- 완료 후: `몽글: 하나 끝냈네. 다음 일 전에 잠깐 쉬어도 좋아.`
- 할 일 없음: 정기 알림을 보내지 않는다.

### 한 번에 하나씩 확인하기

몽글이는 선택된 다음 할 일 하나만 이름으로 말하며 완료 여부를 묻는다. 알림과 위젯 말풍선에는 `수학 숙제 했어?`처럼 질문 하나와 다음 세 응답을 제공한다.

- `했어`: 해당 작업을 완료 처리하고 다음 미완료 작업을 한 번만 소개한다.
- `하는 중`: 현재 작업을 유지하고 사용자가 선택한 잔소리 간격이 지난 뒤 같은 작업을 다시 확인한다.
- `나중에`: `30분 뒤`, `1시간 뒤`, `오늘 저녁` 중 다시 물을 시간을 선택하게 하고, 그동안 수행할 다른 작업이 있으면 하나만 제안한다.

사용자가 답하지 않으면 새 질문을 누적하거나 여러 알림을 연속 발송하지 않는다. 다음 정규 알림 시점에 같은 작업을 한 번만 다시 묻는다. 홈 위젯과 알림의 답변은 동일한 `TaskCheckInResponse` 이벤트로 저장하며, 가장 최근 응답만 적용한다.

방해 금지 시간에는 알림과 말풍선 갱신을 생략한다. 방해 금지 종료 후 누락된 알림을 소급해서 보내지 않고 다음 정규 간격부터 재개한다. 사용자가 잔소리를 끄거나 오늘 할 일을 모두 완료하면 예약 작업을 취소한다.

## 홈 화면 위젯

### 공통 정보

- 오늘 남은 할 일 개수
- 지금 할 일 또는 다음 할 일 제목
- 완료 체크
- 몽글 캐릭터와 짧은 말풍선
- 앱의 오늘 화면을 여는 동작
- 마지막 동기화 시간과 오류 시 새로고침 동작

### 크기

- 작은 위젯: 다음 할 일 한 개, 남은 개수, 몽글 말풍선
- 중간 위젯: 최대 세 개의 오늘 할 일과 완료 체크
- 큰 위젯은 첫 버전에서 제외한다.

### 플랫폼 동작

Android는 위젯 완료 버튼을 WorkManager와 앱 공유 저장소에 반영한다. iOS는 AppIntent를 통해 완료 상태를 기록하고 WidgetKit 타임라인을 갱신한다. 운영체제 제한 때문에 위젯이 매초 갱신된다고 약속하지 않으며, 앱 저장·완료·잔소리 시점에 명시적으로 갱신을 요청한다.

## 데이터와 동기화

공통 `Task` 모델에 다음 필드를 확장한다.

- `dueAt`: 선택 날짜·시간
- `orderAfterTaskId`: 선행 작업 참조
- `source`: `manual | local_parser`
- `parseConfidence`: 선택적 신뢰도

확인 응답은 `TaskCheckInResponse { taskId, action: 'done' | 'in_progress' | 'later', remindAt?, respondedAt }`로 저장한다. `later`에는 반드시 미래의 `remindAt`이 있어야 하며, 해당 시각 전에는 같은 작업을 다시 묻지 않는다.

설정에는 `nudgeIntervalMinutes: 0 | 30 | 60 | 120`를 추가한다. 위젯 공유 데이터는 개인 사진이나 전체 설명을 포함하지 않고 오늘 할 일의 최소 필드만 저장한다.

앱에서 할 일 또는 잔소리 설정이 바뀌면 다음 순서로 처리한다.

1. 공통 저장소에 먼저 저장한다.
2. 네이티브 브리지로 최소 위젯 스냅샷을 전달한다.
3. 위젯 갱신과 다음 알림을 예약한다.
4. 네이티브 갱신이 실패해도 공통 저장은 유지하고 앱에 재시도 상태를 표시한다.

위젯에서 완료한 작업은 앱 재개 시 공통 저장소로 병합한다. 동일 작업의 충돌은 가장 최근 `updatedAt`을 우선한다.

## 화면 구성

오늘 화면의 빠른 입력을 여러 줄 자연어 입력으로 확장한다. `정리하기`를 누르면 전체 화면을 바꾸지 않고 아래에 초안 카드 목록을 표시한다. 각 카드는 제목, 날짜, 시간, 중요도, 예상 시간, 순서를 수정할 수 있다. `모두 저장`과 `취소`를 분리한다.

설정 화면에는 다음 항목을 추가한다.

- 몽글 알림 간격
- 알림과 위젯 말풍선 사용 여부 안내
- 기존 방해 금지 시작·종료 시간
- 홈 위젯 추가 방법

## 권한과 개인정보

- 알림 권한은 사용자가 잔소리 기능을 처음 켤 때 요청한다.
- 권한이 거부되면 위젯 말풍선은 계속 사용하고 설정에 복구 방법을 보여준다.
- 자연어 입력, 할 일 목록, 완료 기록을 광고·분석 서비스로 보내지 않는다.
- 공유 위젯 저장소에는 표시용 최소 정보만 둔다.

## 오류 처리

- 분석 결과가 없으면 원문을 한 개의 할 일로 제안하고 확인을 요청한다.
- 날짜나 시간이 모호하면 `확인 필요` 상태를 표시한다.
- 네이티브 기능을 사용할 수 없는 웹 환경에서는 앱 안의 고정 `지금 할 일` 카드와 브라우저 알림 설정만 제공한다.
- 위젯 동기화 실패는 할 일 저장 실패로 처리하지 않는다.
- 알림 권한 거부, 운영체제 절전 제한, 위젯 미설치를 각각 구분해 안내한다.

## 테스트 기준

- 파서 단위 테스트: 작업 분리, 날짜·시간, 순서, 모호성, 빈 입력
- 초안 화면 테스트: 분석만으로 저장되지 않음, 수정 후 일괄 저장, 취소 시 원본 유지
- 잔소리 정책 테스트: 30·60·120분, 끄기, 할 일 없음, 방해 금지, 소급 알림 없음
- 확인 대화 테스트: 한 번에 한 작업, 했어 완료 처리, 하는 중 재확인, 나중에 유예, 미응답 알림 비누적
- 저장소 테스트: 할 일과 설정의 영속성 및 충돌 병합
- 브리지 계약 테스트: 위젯 스냅샷 최소 필드와 실패 복구
- Android 테스트: 위젯 표시·완료·WorkManager 예약
- iOS 테스트: WidgetKit 표시·AppIntent 완료·타임라인 갱신
- 기존 PWA 회귀 테스트: 다섯 탭, 몽글 캐릭터, 사진 개인화, 메시지 예약

## 완료 조건

- 한 문장 입력을 여러 할 일 초안으로 정리하고 확인 후 저장할 수 있다.
- 잔소리 간격을 끄기·30분·1시간·2시간으로 설정할 수 있다.
- 방해 금지 시간과 할 일 없음 조건에서 알림이 발생하지 않는다.
- 몽글이가 할 일을 하나씩 묻고 `했어·하는 중·나중에` 응답에 맞게 다음 질문을 결정한다.
- Android와 iOS 홈 위젯에서 오늘 할 일과 몽글 말풍선을 확인하고 완료 처리할 수 있다.
- 네이티브 기능이 없는 웹에서도 앱 안의 지금 할 일 표시가 유지된다.
- 기존 데이터와 기능이 손상되지 않고 전체 회귀 검증을 통과한다.
