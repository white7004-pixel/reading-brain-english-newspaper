# 우선순위·사용자 분류 할 일 목록 설계

## 목표

오늘 화면에서 사용자가 해야 할 일을 빠짐없이 훑고, 가장 중요한 일부터 바로 시작할 수 있게 한다. 기존 `지금 할 일` 카드는 한 가지 행동에 집중시키는 역할을 유지하며, 그 아래에 전체 할 일을 우선순위 순으로 보여주는 목록을 추가한다.

## 사용자 경험

- 오늘 화면의 `지금 할 일` 아래에 `오늘의 우선순위` 섹션을 배치한다.
- 상단 필터는 `전체`와 저장된 분류를 가로 스크롤 탭으로 제공한다.
- 기본 분류는 `일`, `개인`, `운동`, `독서`, `취미`다.
- 사용자는 할 일 검토 화면에서 분류를 선택하거나 새 분류를 즉시 추가할 수 있다.
- 분류 관리 화면에서 이름과 대표 색상을 편집하고 사용자 분류를 삭제할 수 있다.
- 목록 행에는 순번, 제목, 분류 색상/이름, 우선순위, 예상 시간, 선택적으로 마감 시간을 표시한다.
- 현재 집중 중인 할 일은 보라색 테두리와 `지금 집중` 표시로 강조한다.
- 미완료 항목을 먼저 표시하고 완료 항목은 목록 아래에 취소선과 함께 표시한다.

## 정렬 규칙

선택된 분류 안에서 다음 순서를 안정적으로 적용한다.

1. 미완료가 완료보다 앞선다.
2. `active` 상태가 다른 미완료 항목보다 앞선다.
3. 우선순위가 높은 순서(`3 → 2 → 1`)로 정렬한다.
4. 마감 시간이 있는 항목은 없는 항목보다 앞서며, 빠른 마감이 먼저다.
5. 조건이 같으면 생성 시간이 빠른 항목이 먼저다.

정렬은 표시 전용이며 사용자가 저장한 할 일 데이터 순서를 임의로 다시 쓰지 않는다.

## 데이터 모델

### 분류

`TaskCategory`의 고정 문자열 유니언 대신 분류 ID를 참조하는 구조로 전환한다.

```ts
interface Category {
  id: string
  name: string
  color: string
  isDefault: boolean
  createdAt: string
  updatedAt: string
}
```

기본 분류는 안정적인 ID(`work`, `personal`, `exercise`, `reading`, `hobby`)를 사용한다. 기존 데이터의 `study`, `life`, `rest`는 읽을 때 각각 `personal`, `personal`, `hobby`로 마이그레이션한다. 기존 `work`, `exercise`는 그대로 유지한다.

할 일은 `categoryId`를 저장한다. 이전 버전의 `category` 필드가 있는 레코드는 저장소 정규화 과정에서 `categoryId`로 변환해 기존 사용자의 데이터를 보존한다.

### 저장소

- IndexedDB에 `categories` 테이블을 추가하고 앱 시작 시 기본 분류를 멱등적으로 생성한다.
- 사용자 분류 이름은 앞뒤 공백을 제거하며 빈 이름과 대소문자/공백 정규화 후 중복 이름을 허용하지 않는다.
- 기본 분류는 삭제할 수 없다.
- 사용자 분류 삭제는 하나의 트랜잭션에서 해당 분류의 모든 할 일을 `personal`로 옮긴 뒤 분류를 삭제한다.
- 색상은 앱이 제공하는 접근성 확인 팔레트에서 선택하므로 임의 CSS 문자열은 저장하지 않는다.

## 할 일 입력과 자동 분류

- 한 개 저장과 AI식 다중 정리 모두 기본값을 `개인`으로 사용한다.
- 로컬 파서는 제목의 명확한 단어를 기준으로 기본 분류를 추천한다. 예: `회의/보고서`는 일, `헬스/달리기`는 운동, `책/독서`는 독서.
- 자동 추천은 확정이 아니다. 저장 전 검토 화면에서 모든 항목의 분류를 수정할 수 있다.
- 사용자 정의 분류는 명시적으로 선택할 수 있지만 초기 버전에서 자유 텍스트 의미 추론 대상으로 사용하지 않는다. 잘못된 자동 분류를 줄이기 위한 제한이다.

## 구성 요소

- `categoryRepository`: 기본값 생성, 조회, 추가, 수정, 삭제 및 기존 데이터 이동을 담당한다.
- `sortPriorityTasks`: 필터와 정렬을 담당하는 순수 함수다.
- `PriorityTaskList`: 분류 탭과 정렬된 목록을 표시한다.
- `CategoryPicker`: 할 일 검토에서 기존 분류 선택과 새 분류 추가를 제공한다.
- `CategoryManager`: 설정 화면에서 사용자 분류 이름·색상 편집과 삭제를 제공한다.
- `TodayScreen`: 할 일과 분류를 로드하고 현재 추천 항목과 전체 목록에 같은 데이터를 전달한다.

## 접근성과 반응형

- 색상만으로 분류나 우선순위를 구분하지 않고 항상 텍스트 라벨을 함께 표시한다.
- 탭은 키보드 포커스와 `aria-pressed` 상태를 제공한다.
- 목록은 시각적으로 촘촘하게 구성하되 터치 영역은 최소 44px을 유지한다.
- 작은 화면에서는 부가 정보가 두 번째 줄로 줄바꿈되며 가로 페이지 스크롤은 만들지 않는다.
- 모션 감소 설정에서는 강조 애니메이션을 사용하지 않는다.

## 오류 및 빈 상태

- 해당 분류에 항목이 없으면 `이 분류에는 아직 할 일이 없어요.`를 표시한다.
- 분류 저장 실패 시 입력값을 유지하고 화면 내 오류 메시지를 제공한다.
- 삭제 중 데이터 이동이 실패하면 트랜잭션 전체를 취소해 분류와 할 일 연결을 보존한다.
- 알 수 없는 분류 ID의 할 일은 화면에서 `개인`으로 표시하고 다음 저장 시 정규화한다.

## 테스트와 완료 기준

- 정렬 함수가 상태, 우선순위, 마감, 생성 시간 규칙을 정확히 적용한다.
- 전체/분류 탭이 올바른 항목만 표시한다.
- 현재 집중 항목과 완료 항목의 상태가 접근 가능한 텍스트로 드러난다.
- 기본 분류 초기화가 중복 레코드를 만들지 않는다.
- 사용자 분류 추가 시 빈 이름과 중복 이름을 거부한다.
- 사용자 분류 삭제 시 연결된 할 일이 `개인`으로 이동하며, 실패 시 원상태가 유지된다.
- 기존 분류 값을 가진 할 일이 데이터 손실 없이 새 ID로 변환된다.
- 할 일 검토에서 기본/사용자 분류를 선택해 저장할 수 있다.
- 전체 웹 테스트, 프로덕션 빌드, Capacitor 동기화, Android 단위 테스트·lint·APK 빌드를 통과한다.
- 최신 APK를 에뮬레이터에 설치하고 오늘 화면의 목록과 분류 필터를 실제 화면으로 확인한다.

## 제외 범위

- 분류별 아이콘 업로드
- 사용자 정의 분류를 대상으로 한 의미 기반 AI 자동 추론
- 분류의 중첩 또는 하위 분류
- 드래그 앤 드롭 수동 정렬
- 서버 계정 간 분류 동기화
