## 파일

```
학원만족도조사/
  survey/                  ← Vercel 프로젝트 루트 (빌드 없음)
    index.html             설문 (/parent · /student · /teacher 가 모두 이 파일, 주소로 설문 고름)
    results.html           결과 (cleanUrls 로 /results)
    questions.js           문항 목록 (두 화면 공용)
    core.js                검사·집계·CSV·저장 통로 (두 화면 공용, config.js 가 비면 연습 모드)
    check.js               node 자가검사
    logo.png
    config.js              Supabase 주소·공개 키
    vercel.json
  supabase/001_academy_survey.sql   원장이 SQL Editor에 한 번 붙여 넣음
  supabase/test-sql.mjs             PGlite 로 SQL 시험
```

## 데이터

- `academy_survey.responses`: `id`, `created_at`, `survey`(`parent` · `student` · `teacher`), `answers jsonb`(문항 번호→답).
- `academy_survey.settings`: 결과 비밀번호 해시(pgcrypto `crypt`).
- 칸 `academy_survey` 는 API에 노출하지 않는다. 바깥에서 부르는 것은 `public` 의 함수 둘뿐이다.
  - `survey_submit(p_survey text, p_answers jsonb)`: 넣기만 한다. 설문 이름·모양(객체, 20KB·60칸 이하)을 확인하고 글은 2,000자로 자른다. 필수 문항 검사는 화면에서만 한다(문항 목록을 SQL 에 두 벌 두지 않으려고 — 무기명 설문이라 엉터리 답은 잡음일 뿐).
  - 학생 설문은 태블릿을 돌려 쓰므로 "같은 폰 재참여 막기"를 하지 않고 끝나면 "다음 친구 시작"을 보여 준다(학부모만 막음).
  - `survey_results(p_password text, p_survey text)`: 틀리면 0.5초 늦게 null. 비밀번호가 맞을 때만 그 설문의 응답을 돌려준다. 틀리면 빈 결과를 준다.
- 두 함수 모두 `security definer` 로 둔다. anon 에게는 실행 권한만 주고, 표에 대한 직접 권한은 주지 않는다.

## 설문 화면 흐름

1. 첫 화면: 인사말과 무기명 안내, "시작하기" 단추
2. 섹션 단위 단계(학부모: 학생 레벨 → 교수팀·수업 → 운영팀 → 자유의견 / 학생: 학년 → 수업과 선생님 → 내 생각 적기): 위에 단계 수만큼 진행 막대. 필수 문항을 빠뜨리면 그 문항 옆에 빨간 안내가 나오고 넘어가지 않는다
3. 제출: 저장 중에는 단추를 잠근다. 실패하면 "다시 보내기"를 보여 주고, 적은 답은 지우지 않는다
4. 감사 화면. 폰에 제출 표시를 남겨, 같은 폰으로 다시 열면 "이미 참여하셨습니다"가 나온다 (막는 힘이 약하다는 것을 알고 쓴다)
- 폰 375px 기준으로 만들고, 터치 영역은 44px 이상으로 한다. 쓰는 사람이 학부모라 다크모드는 두지 않고 밝은 화면 하나로 간다.

## 결과 화면

- 비밀번호 입력 → 맞으면 그 기기에 기억한다(sessionStorage)
- 맨 위: 응답 수와 섹션별 5점 평균(학부모: 교수팀·운영팀 / 학생: 수업과 선생님)
- 위에서 설문 종류(학부모·학생·강사) 고르기
- 거르기: 학년, 커리큘럼(학부모 설문만. 여러 개 고른 응답은 고른 반마다 센다)
- 문항별 가로 막대(개수와 %). 5점 문항에는 평균을 함께 보여 준다
- 서술 문항: 카드 목록, 학년(·커리큘럼) 꼬리표
- CSV 내려받기(엑셀에서 한글이 깨지지 않게 BOM 포함)
- 새로고침 단추. 실시간 자동 갱신은 두지 않는다 — 필요하면 그때 넣는다

## 확인 방법

- 문항 목록 검사: `questions.js` 의 문항·보기가 이 문서의 표들과 같은지 확인하는 작은 node 스크립트
- 집계 함수(평균·거르기·CSV)는 화면 코드와 떼어서 `assert` 자가검사를 붙인다
- 브라우저: 폰 크기로 설문을 끝까지 제출하고 → 결과 화면에서 그 응답이 보이는지 확인. 비밀번호가 틀리면 아무것도 안 나오는지도 본다

## 하지 않는 것

- 문항 편집 화면 (문항은 `questions.js` 를 고친다)
- 로그인, 학생별 추적, 알림톡 발송
- 여러 학원용 범용화 (그건 9/3 도구의 몫)

## 설문 만들기 (10/1 원장 승인 — 리딩브레인용 먼저, 나중에 다른 원장님께 넓힘)

- **문항을 서버에 둔다.** `academy_survey.forms(slug, def, status, sort)` — def 는 questions.js 와 같은 모양
  (+ `greeting` 첫 인사, `thanks` 끝 인사). parent·student 는 questions.js 로 처음 값을 넣고, questions.js 는 서버를 못 읽을 때의 대비로만 남긴다.
- 주소: 기존 `/parent` `/student` 그대로, 새 설문은 `/s/<slug>` (slug = 영문 소문자·숫자·`-`, 2~40자).
- **응답이 생긴 설문의 고치기 규칙은 서버가 지킨다**: 옛 문항이 모두 같은 id·같은 종류·같은 보기로 남아 있어야 저장(글자 고치기·문항 더하기만).
  아니면 "복사해서 새 설문". 응답 없는 설문만 지울 수 있다. 닫힌 설문은 "마감되었습니다".
- 함수(모두 security definer): 공개 `survey_form(slug)`, 바뀐 `survey_submit`(열린 설문만), 비밀번호 `survey_admin_forms`·`survey_save_form`·`survey_set_status`·`survey_delete_form`.
- 대시보드 탭: 전체 보기 · 설문 관리(목록·새 설문·고치기·복사·열기/닫기·지우기) · (고른 설문의 결과|설문지).
  고치기 화면은 왼쪽 폰 미리보기가 postMessage 로 바로바로 바뀐다. 거르기는 `filter: true` 인 문항이면 무엇이든.
- **관리시스템 연결**: 관리시스템 메뉴에 "설문" 한 칸 — 이 대시보드를 iframe 으로 띄운다(화면을 두 벌 만들지 않음). 관리시스템 배포 전에 원장에게 다시 묻는다.
- 하지 않음: 다른 원장님 가입·계정 분리, 결제, 문항 창고.
