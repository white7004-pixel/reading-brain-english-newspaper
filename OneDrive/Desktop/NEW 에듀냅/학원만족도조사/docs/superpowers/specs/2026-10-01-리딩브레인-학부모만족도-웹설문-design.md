섹션 머리말·안내 문구도 구글폼 원문을 그대로 쓴다. 문항은 `survey/questions.js` 한 곳에만 둔다.
설문 화면과 결과 화면이 둘 다 이 목록을 읽는다.

## 파일

```
학원만족도조사/
  survey/                  ← Vercel 프로젝트 루트 (빌드 없음)
    index.html             설문
    results.html           결과 (vercel.json 으로 /results)
    questions.js           문항 목록 (두 화면 공용)
    config.js              Supabase 주소·공개 키
    vercel.json
  supabase/001_academy_survey.sql   원장이 SQL Editor에 한 번 붙여 넣음
```

## 데이터

- `academy_survey.responses`: `id`, `created_at`, `survey`(기본 `'2027-parent'`), `answers jsonb`(문항 번호→답).
- `academy_survey.settings`: 결과 비밀번호 해시(pgcrypto `crypt`).
- 칸 `academy_survey` 는 API에 노출하지 않는다. 바깥에서 부르는 것은 `public` 의 함수 둘뿐이다.
  - `survey_submit(answers jsonb)`: 넣기만 한다. 필수 문항·보기 값을 서버에서 다시 확인하고, 서술은 2,000자로 자른다.
  - `survey_results(password text)`: 비밀번호가 맞을 때만 전체 응답을 돌려준다. 틀리면 빈 결과를 준다.
- 두 함수 모두 `security definer` 로 둔다. anon 에게는 실행 권한만 주고, 표에 대한 직접 권한은 주지 않는다.

## 설문 화면 흐름

1. 첫 화면: 구글폼 인사말과 무기명 안내, "시작하기" 단추
2. 단계 1~4(학생 레벨 → 교수팀·수업 → 운영팀 → 자유의견): 위에 4칸 진행 막대. 필수 문항을 빠뜨리면 그 문항 옆에 빨간 안내가 나오고 넘어가지 않는다
3. 제출: 저장 중에는 단추를 잠근다. 실패하면 "다시 보내기"를 보여 주고, 적은 답은 지우지 않는다
4. 감사 화면. 폰에 제출 표시를 남겨, 같은 폰으로 다시 열면 "이미 참여하셨습니다"가 나온다 (막는 힘이 약하다는 것을 알고 쓴다)
- 폰 375px 기준으로 만들고, 터치 영역은 44px 이상으로 한다. 쓰는 사람이 학부모라 다크모드는 두지 않고 밝은 화면 하나로 간다.

## 결과 화면

- 비밀번호 입력 → 맞으면 그 기기에 기억한다(sessionStorage)
- 맨 위: 응답 수, 교수팀 5점 평균, 운영팀 5점 평균
- 거르기: 학년, 커리큘럼(여러 개 고른 응답은 고른 반마다 셉니다)
- 문항별 가로 막대(개수와 %). 5점 문항에는 평균을 함께 보여 준다
- 자유의견 12·13번: 카드 목록, 학년·커리큘럼 꼬리표
- CSV 내려받기(엑셀에서 한글이 깨지지 않게 BOM 포함)
- 새로고침 단추. 실시간 자동 갱신은 두지 않는다 — 필요하면 그때 넣는다

## 원장이 직접 하실 일

1. Supabase(readingbrain 조직 원서 프로젝트) → SQL Editor → `001_academy_survey.sql` 붙여 넣고 실행. 그 안의 비밀번호 한 줄만 바꾼다
2. Vercel 배포를 허락한다(제가 올리고 주소를 드림)

## 확인 방법

- 문항 목록 검사: `questions.js` 의 13문항·보기가 이 표와 같은지 확인하는 작은 node 스크립트
- 집계 함수(평균·거르기·CSV)는 화면 코드와 떼어서 `assert` 자가검사를 붙인다
- 브라우저: 폰 크기로 설문을 끝까지 제출하고 → 결과 화면에서 그 응답이 보이는지 확인. 비밀번호가 틀리면 아무것도 안 나오는지도 본다

## 하지 않는 것

- 문항 편집 화면 (문항은 `questions.js` 를 고친다)
- 로그인, 학생별 추적, 알림톡 발송
- 여러 학원용 범용화 (그건 9/3 도구의 몫)
