# 리딩브레인 웹설문 (학부모·학생) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** 학부모·학생 웹설문과 비밀번호 결과 화면을 정적 파일로 만들고, Supabase SQL 을 준비한다.

**Architecture:** 빌드 없는 HTML 두 장(`index.html` 설문, `results.html` 결과)이 `questions.js`(문항)와 `core.js`(검사·집계·CSV·저장 통로)를 같이 읽는다. 저장은 Supabase `public.survey_submit` / `survey_results` 함수(RPC)로만 한다. `config.js` 가 비어 있으면 localStorage 연습 모드.

**Tech Stack:** 순수 HTML/CSS/JS(옛 사파리 대비 `?.` 안 씀), Supabase REST RPC, node 자가검사, Vercel 정적 배포.

**Spec:** `docs/superpowers/specs/2026-10-01-리딩브레인-학부모만족도-웹설문-design.md`

## Global Constraints

- 문항·보기 글자는 설계서 표 그대로. 다른 학원 이름을 어디에도 쓰지 않는다.
- 시안 B 색: 바탕 `#FBF8F3`, 레드 `#B7161F`, 본문 `#3A2E2A`, 선 `#D9CBBE`, 흐린 글 `#7A6A60`. 제목 세리프.
- 터치 영역 44px 이상, 375px 폭 기준, 가로 스크롤 없음.
- 무기명. 비밀번호를 페이지에 적지 않는다.

### Task 1: 문항과 핵심 로직 (`survey/questions.js`, `survey/core.js`, `survey/check.js`)

- Produces: `SURVEYS[id] = {id,title,kicker,intro[],sections:[{title,desc,items:[{id,type,label,options,required,noAvg,flag}]}]}`;
  type ∈ `single|multi|scale|text`; scale options = `[{v,label}]`(화면 순서).
  `RB.missing(survey,answers) → [itemId]`, `RB.summarize(survey,rows) → {n, sections:[{title,avg}], items:{id:{counts,avg}}}`,
  `RB.filterRows(rows,{grade,curriculum})`, `RB.toCSV(survey,rows) → string(BOM)`, `RB.flagged(survey,rows)`,
  `RB.api.submit(surveyId,answers) → Promise`, `RB.api.results(password,surveyId) → Promise<rows|null>`.
- [ ] check.js 에 assert 작성(문항 수 14·21, 필수 누락, 평균, 거르기, CSV) → 실패 확인
- [ ] questions.js·core.js 작성 → `node survey/check.js` 통과

- [ ] 브라우저(375px)로 학부모·학생 끝까지 제출(연습 모드)
