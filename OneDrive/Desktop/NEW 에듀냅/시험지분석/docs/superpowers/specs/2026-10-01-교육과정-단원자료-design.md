# 교육과정 단원 자료 (국어·영어·수학) — 설계서

앞 설계서: `2026-09-15-시험지분석-design.md` (문항표·A4 리포트) · `2026-09-30-공유카드-design.md` (분석표·카드)

## 0. 한 줄

국어·영어·수학의 **영역과 성취기준**을 학년(과목)마다 자료로 갖추고, 그것을 AI 추출 계약과 확인 표에 물려
**시험지마다 갈리던 단원·영역 이름을 하나로 모은다.**

## 1. 왜 (지금 무엇이 문제인가)

문항의 `unit`(단원)과 `area`(영역)을 AI 가 시험지에서 읽은 대로 자유롭게 적는다. 그래서

- 같은 단원이 "5과" · "Lesson 5" · "5단원" 으로 갈려 **단원별 출제 표가 흩어진다**
- 영역은 과목별 고정 목록(`SUBJECTS`)이라 **학년을 구분하지 못한다** — 중학교 국어의 "문학"과 고등 「문학」이 같은 칸에 들어간다
- 세부 포인트(`subtype`)에 기댈 기준이 없어 AI 가 매번 다른 말로 적는다

## 2. 정한 것 (원장님 결정, 2026-10-01)

| 항목 | 결정 |
|---|---|
| 기준 | **2022 개정 교육과정을 뼈대로.** 교과서 목차는 원장님이 실제로 쓰는 것만 나중에 덧붙인다 |
| 넣을 곳 | **AI 계약(`lib/rules.js`)과 확인 표 둘 다** |
| 고등 범위 | **내신에 실제로 나오는 과목만** (아래 3장) |
| 순서 | 국어 → 영어(+문법) → 수학. 과목마다 따로 커밋 |
| 영어 문법 | 교육과정에 없다. 내신 문법 항목표를 따로 만들고 **`[학원분류]`** 로 표시한다 |

## 3. 범위

자료는 `curriculum-kr-secondary` MCP(2022 개정 교육과정)에서 **코드째로 받아** 넣는다.
기억으로 쓰는 문장은 한 줄도 없다.

| 과목 | 중학교 | 고등학교 |
|---|---|---|
| 국어 | 국어 (51) | 공통국어1, 공통국어2, 화법과 언어, 독서와 작문, 문학 |
| 수학 | 수학 (60) | 공통수학1, 공통수학2, 대수, 미적분Ⅰ, 확률과 통계 |
| 영어 | 영어 (21) | 공통영어1, 공통영어2, 영어Ⅰ, 영어Ⅱ, 영어 독해와 작문 |

18개 과정, 성취기준 약 330개.

**중학교 교육과정은 중1/2/3 을 가르지 않는다** (학년군 7–9). 학년을 가르는 것은 교과서다.
그래서 중학교 과정 하나가 중1·중2·중3 셋 모두에 걸린다. 학년별로 좁히는 것은 `교과서` 자료가 들어온 뒤의 일이다.

**고1·2·3 도 학년이 아니라 과목이다.** 고1 은 공통 과목, 고2·3 은 선택 과목으로 잡는다.

## 4. 자료 — `data/curriculum/`

과목마다 파일 하나: `국어.json` `영어.json` `수학.json`, 그리고 `영어문법.json`.

```jsonc
{
  "과목": "국어",
  "출처": "2022 개정 교육과정 (교육부 고시 제2022-33호)",
  "받은날": "2026-10-01",
  "과정": [
    {
      "id": "kr-2022-middle-국어",
      "이름": "중학교 국어",
      "학년": ["중1", "중2", "중3"],
      "영역": [
        {
          "이름": "문법",
          "성취기준": [
            { "코드": "[9국04-01]", "요약": "국어의 음운 체계와 문자 체계를 이해하고 국어생활에 활용하기" }
          ]
        }
      ]
    }
  ],
  "교과서": []
}
```

`교과서` 는 지금 빈 배열이다. 원장님이 쓰시는 교과서를 알려 주시면
`{ "출판사": "동아", "저자": "이병민", "학년": "중2", "단원": ["1과 …", "2과 …"] }` 로 덧붙인다.
**목차를 받기 전에는 채우지 않는다.**

## 5. 영어 문법 — `영어문법.json`

교육과정 영어 성취기준은 의사소통 기능 중심이라 **문법 항목 목록이 없다.**
그래서 중등·고등 내신에 실제로 나오는 항목을 학년대별로 정리하고, 모든 줄에 `"출처": "[학원분류]"` 를 붙인다.

```jsonc
{
  "이름": "영어 내신 문법",
  "출처": "[학원분류] — 교육과정 성취기준이 아니라 내신 출제 관행에 따른 분류. 원장님 검수 필요",
  "묶음": [
    { "이름": "시제", "학년대": ["중1", "중2", "중3"],
      "항목": ["현재·과거·미래", "현재진행·과거진행", "현재완료 — 경험·계속·완료·결과"] }
  ]
}
```

이 파일은 **원장님 검수를 받기 전까지 확정이 아니다.** 검수 뒤 이 설계서에 결정을 적는다.

## 6. 앱에 물리기

### 6-1. `public/curriculum.js` — 얇은 조회 층

자료를 읽어 세 가지만 내준다. 계산도, 화면 그리기도 하지 않는다.

- `areasFor(과목, 학년)` → 그 학년 과정의 영역 이름 배열
- `unitsFor(과목, 학년)` → 단원 후보 (교과서 목차가 있으면 그것, 없으면 영역)
- `pointsFor(과목, 학년)` → 성취기준 요약 배열 (세부 포인트 후보)

셋 다 **모르는 과목·학년이면 빈 배열**을 돌려준다. 부르는 쪽이 기존 `SUBJECTS` 로 물러설 수 있게 한다.

### 6-2. `lib/rules.js` — AI 가 목록 안에서 고르게

추출 프롬프트에 그 학년의 영역·단원 후보·성취기준을 넣는다.
`area` 는 지금도 enum 이다. 학년을 알면 그 학년 목록으로, 모르면 지금처럼 `SUBJECTS` 목록으로 만든다.
`unit` 은 **enum 으로 묶지 않는다** — 교과서 단원은 목록 밖에 있을 수 있고, 시험지에 적힌 말이 우선이다.
대신 "목록에 같은 뜻이 있으면 목록의 말로 적는다"를 프롬프트로 못 박는다.

### 6-3. `public/app.js` — 확인 표에 고를 수 있는 칸

단원·영역 칸에 `<datalist>` 를 붙인다. **자유 입력은 그대로 된다.**
목록에 없는 교과서를 쓰는 학교에서 막히면 안 된다.

## 7. 지킬 것

- 자료의 모든 줄은 **출처가 있다.** 교육과정에서 받은 것과 `[학원분류]` 를 섞지 않는다.
- 성취기준 문장은 MCP 가 준 그대로 넣는다. 다듬지 않는다.
- 학년을 모르면 지금 동작 그대로다. 자료가 없다고 리포트가 깨지지 않는다.
- 교과서 목차는 출처(원장님이 주신 목차·교과서 사진) 없이 채우지 않는다.

## 8. 검사

`node --test` 에 붙인다.

- 자료 세 개가 스키마를 지킨다 (과목·출처·과정·영역·성취기준이 모두 있고, 빈 문자열이 없다)
- 성취기준 코드가 파일 안에서 겹치지 않는다
- 중1~중3·고1~고3 여섯 학년 모두 `areasFor` 가 빈 배열이 아니다 (국어·영어·수학 셋 다)
- `unitsFor` 는 교과서 목차가 없으면 영역을 돌려준다
- 모르는 과목·학년에 빈 배열을 돌려준다
- 영어 문법표에 같은 항목이 두 번 없고, 모든 묶음에 `[학원분류]` 출처가 붙어 있다
- `lib/rules.js` 가 학년을 받으면 그 학년 영역으로 enum 을 만들고, 못 받으면 `SUBJECTS` 로 만든다
