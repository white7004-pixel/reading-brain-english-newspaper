## 0. 한 줄

확인한 문항표에서 **공개용 A4 분석표 1장**을 만들고, 같은 숫자·같은 표를 그대로 **카드뉴스 3장**으로 쪼개
학부모 단톡방·학원 블로그에 올릴 수 있게 한다.

## 1. 정한 것 (원장님 결정, 2026-09-30)

| 항목 | 결정 |
|---|---|
| 결과물 | 카톡·블로그용 **이미지 카드** (A4 1장을 먼저 만들고 쪼개서 3장) |
| 학생 결과 | **넣지 않는다.** 학교 시험 분석만 공개한다 |
| 문항 출처 | **넣되, 확인 표에서 원장님이 고친다** (교과서·부교재·외부·기출변형, 모르면 빈 칸) |
| 과목 | 국어·영어·수학·과학·사회·역사 (본체와 같음) |
| 카드 크기 | 1080×1350 (카톡·블로그·인스타 공통으로 무난한 세로) |

## 2. 조사에서 가져온 것 (2026-09-30)

학원 블로그 시험분석 글 12편(수학·일반 6, 영어 5, 국어 1)을 본문까지 받아 읽었다.
공통으로 확인된 것:

- 분석의 알맹이는 **글이 아니라 표**다. 막대 그림만 있는 글은 없다.
- 늘 나오는 표: 유형(객관식·서술형)별 · 난이도별 · 영역(단원)별 · **배점별** · **출처별**(교과서/부교재/외부/기출변형)
- 표에는 비율만이 아니라 **문항 번호**를 함께 적는다 ("5점 문항 5개가 전부 어법")
- 끝에 변별 문항 몇 개와 그 이유, 다음 시험 대비 방법
- 넣지 않는 것: 학생 이름·점수, 시험지 원문 이미지, "최고·1등" 같은 단정

**첫 판(막대 중심)이 허전했던 이유가 이것이다.** 그래서 표 중심으로 다시 짰다.

## 3. A4 분석표 1장 (공개용)

위에서 아래로:

| 자리 | 내용 | 출처 |
|---|---|---|
| 머리 | 학원 로고·이름, `학교 학년 학기 시험 과목 분석`, 문항 수·만점·전체 난이도 | 학원 정보(로그인) + meta |
| 핵심 수치 4 | 전체 문항 · 총 배점 · 서술형 배점 비율(문항 수) · 중상 이상 비율(문항 수·배점) | `examStats` |
| 총평 | 한 줄 평 + 전체 난이도 뱃지 | AI 글(overview) |
| 시험 구성 표 | 구분(유형·난이도·출처) × 항목 × 문항 수 × 배점 × 비율(막대) | `byKind` `byDifficulty` `bySource` |
| 영역별 출제 표 | 영역 · **문항 번호** · 문항 수 · 배점 · 비율(막대) | `byArea` + `nosText` |
| 배점 구성 표 | 배점 · 문항 수 · 문항 번호 | `byPoints` |
| 변별 문항 표 | 번호 · 영역·세부유형 · 배점 · 난이도 · 왜 어려웠나 | 문항표 + AI 글(keyItems) |
| 전 문항 표 | 번호 · 유형 · 영역 · 세부 포인트 · 배점 · 난이도 · 출처 (반으로 갈라 나란히) | 문항표 |
| 대비 표 | 영역 · 준비 방법 | AI 글(strategy) |
| 끝 | 학원 이름·연락처, "난이도·출처는 학원 분류" 한 줄 | 학원 정보 |

## 4. 카드뉴스 3장

같은 `ctx`와 같은 AI 글, **같은 표 만드는 함수**를 쓴다. 카드에서 숫자를 새로 계산하지 않는다.

1. **한눈에** — 핵심 수치 4, 총평, 영역별 출제 표
2. **어떻게 나왔나** — 시험 구성 표(유형·난이도·출처), 점수가 갈린 문항 표
3. **다음 시험 준비** — 준비 방법 표, 배점이 큰 문항 표

각 카드는 `1080×1350` 고정. 글이 많으면 A4 와 같은 `--fit` 배율로 줄인다.

## 5. 구조

- `public/lib.js` — `SOURCES`, `examStats` 에 `byKind` `bySource` `byPoints` `hard`, 영역·유형별 `nos`, `nosText()`
- `public/report.js` — `table()` `num()` `barCell()` 과 표 조각들(`kpi` `composeTable` `areaTable` `pointsTable` `keyTable` `strategyTable` `itemsTable`). `schoolPage` 와 `studentPage` 는 이 조각을 배치만 한다
- `public/share.js` — 카드 3장. `report.js` 의 같은 조각을 가져다 쓴다. `student` 데이터를 받지 않는다
- `public/style.css` — `.t` 표 한 벌(머리글 브랜드색, 숫자 오른쪽, 비율 칸 배경 막대). 카드는 크기만 다르게
- `lib/rules.js` — 문항마다 `source`. 모르면 빈 문자열 + `unsure`

## 6. 지킬 것

- 학생 이름·점수·시험지 원문 사진은 **어느 카드에도 넣지 않는다.** (`share.js` 는 `student` 데이터를 받지 않는다)
- 모든 글자는 `esc()` 를 지난다.
- 숫자는 `public/lib.js` 계산만 쓴다. 표를 만드는 곳에서 계산하지 않는다.

## 7. 구현 결과 (2026-09-30)

- 첫 판(막대·격자)은 원장님이 "디자인이 너무 별로"라고 했다. 블로그 12편을 다시 읽고 **표 중심**으로 갈아엎었다.
- 학생 리포트도 같은 표로 맞췄다 (영역별 결과 표, 오답 분석 표). 한 벌로 인쇄되는 자료라 모양이 달라서는 안 된다.
- 쓰지 않게 된 `bars()` 와 `.bars` `.r-causes` `.r-key` `.r-strategy` 는 지웠다.
- 확인: 22문항 기준 A4 한 장에 `--fit 0.97` 로 들어감(넘침 경고 없음), 카드 3장 1080×1350,
  PNG 저장 A4 1588×2244·카드 2160×2700(표·뱃지·막대 그대로), 카드에 학생 이름 없음, 검사 35개 통과.

## 8. 검증

- 카드 3장에 들어간 숫자가 A4 와 같은지 자동 검사 (`test/share.test.js`)
- 학생 이름이 어떤 카드에도 없는지 자동 검사
- A4 에 표 일곱 개(전 문항 표 두 쪽 포함)가 있고 rowspan·막대·출처 줄임이 맞는지 자동 검사 (`test/report.test.js`)
- 브라우저에서 가짜 시험지로 전체 렌더 → 한 장 맞춤 확인 → PNG 저장 확인
