## 출시를 막는 것 — 둘

### 1. 클로드 API 키 (가장 큰 위험)

**이 PC 에 키가 없어 실제 모델을 한 번도 부르지 못했다.** 지금까지는 전부 가짜 응답으로 확인한 것이다.

- 키는 **`.env.local`** 에 `ANTHROPIC_API_KEY=...` 로 넣는다. **채팅에 붙여넣지 않는다**
- 넣은 뒤 `npm run local` → 실제 시험지 한 벌로 끝까지 돌려 본다
- 볼 것: ① 문항표가 맞는가 ② 정답이 맞는가 ③ 몇 분 걸리는가 ④ `fallbacks` 베타가 받아들여지는가
- **여기서 정답 정확도가 드러난다.** 돌려 보기 전에는 아무도 모른다

### 2. 접속 코드 입력 칸이 화면에 없다

지금 그대로 Vercel 에 올리면 **모든 요청이 401 로 막힌다.**

- 서버(`lib/http.js`)는 인터넷에 올라가면 `TRIAL_CODE` 를 반드시 요구한다
- 그런데 화면이 `x-trial-code` 헤더를 보내지 않는다 (이 PC 에서 쓰려고 뺐다)
- **코드 입력 칸을 다시 붙여야 한다.** 작은 작업이다

## 배포할 때 (원장님이 정하실 것)

1. Vercel 프로젝트 이름
2. 접속 코드 (`TRIAL_CODE`) 를 무엇으로 할지
3. **API 키는 원장님이 Vercel 화면에서 직접 넣으신다**
4. 푸시·배포는 **원장님이 말씀하실 때만** 한다 (브랜치 푸시도 빌드 비용이 든다)

## 출시 뒤에 해도 되는 것

| 할 일 | 왜 급하지 않나 |
|---|---|
| 영어 문법표 원장님 검수 | `[학원분류]` 라 쓰는 데 지장 없다. 쓰면서 고치면 된다 |
| 교과서 목차 넣기 | 없으면 AI 가 시험지에 적힌 단원을 그대로 쓴다 |
| 1단계 학교별 기출 은행 | 설계서만 있다. **지금부터 쌓아야 내년에 경향이 나온다** — 출시 직후 1순위 |
| 2단계 예상문제·적중률 | 기출이 2회 쌓인 뒤에나 가능 |
| 서답형 번호 (`no` 를 문자열로) | 지금은 뒤에 이어 붙인다. **기출 은행 저장 층 만들기 직전**에 고친다 |
| 블로그 코멘트 자동 생성 | 1단계에 들어 있다 |

## 가장 빠른 길

```
① .env.local 에 키 넣기        → 실제 시험지 한 벌 돌려 보기   (원장님)
② 접속 코드 입력 칸 붙이기                                      (나)
③ Vercel 배포 (이름·코드 정하고, 키는 원장님이 직접 입력)
```

②는 지금 바로 할 수 있다. ①이 끝나야 출시해도 되는지 알 수 있다.
