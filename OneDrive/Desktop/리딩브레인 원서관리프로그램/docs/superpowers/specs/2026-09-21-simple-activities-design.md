# 간이 학습(읽고 나서) 설계

**날짜:** 2026-09-21
**승인:** 원장 승인 완료 — 아이가 화면에서 직접 / 세 벌 / AI 가 책마다 따로 / 키 없이 서브에이전트로 생성

## 무엇을 만드나

서재의 **4,820권 전부**에 아이가 읽고 나서 할 수 있는 활동을 붙인다. 9단계 학습이 아니라 한 화면짜리 **간이 학습**이다.

## 왜

9단계 학습은 **책 본문이 있어야** 만들어진다. 낱말 예문(`Buzz caught the fly in a {{jar}}.`), 퀴즈, 요약지도, 독후논술이 전부 줄거리를 안다는 전제 위에 있다. 그런데 목록에 있는 것은 제목·저자·AR·렉사일·갈래·주제·수상과 **한 줄 요약**뿐이다.

13권을 만드는 데 5,763줄이 들었다. 4,820권이면 213만 줄, 낱말 소리 4만 8천 개(약 8GB)다. 무료 호스팅에 올라가지도 않는다.

그래서 **가진 자료로 만들 수 있는 것**만 만든다. 그 대신 한 권도 빠짐없이 만든다.

## 누가 쓰나

**아이가 화면에서 직접** 쓴다. 답을 적으면 이름별로 저장된다. 선생님이 종이로 뽑는 것은 이번에 하지 않는다.

## 세 벌

AR 0.3부터 11.7까지를 같은 질문지로 덮을 수 없다. 세 벌로 나눈다.

| 벌 | AR | 권수 | 무엇을 | 어떻게 답하나 |
|---|---|---:|---|---|
| 1벌 | 0 ~ 1.9 | 1,338 | 그림책·리더스 | **한국어**. 짧게 고르거나 한 줄 |
| 2벌 | 2 ~ 3.9 | 2,527 | 챕터북 | **영어 한 문장**. 한국어 도움말을 함께 보여 준다 |
| 3벌 | 4 이상 | 955 | 소설·논픽션 | **영어 서술**. 한 문단 |

벌은 저장하지 않는다. `BL` 에서 그때그때 셈한다 — 목록이 바뀌어도 따라온다.

## 한 권에 무엇이 들어가나

**AI 가 만드는 것 — 질문 3개**

책마다 다르다. 제목·저자·시리즈·갈래·주제·수상·한 줄 요약을 주고 그 책에 맞는 질문을 쓰게 한다.

**AI 에게 거는 제약 — 줄거리를 단정하지 않는다**

우리가 가진 것은 한 줄 요약뿐이다. "플라이 가이가 병에서 어떻게 나왔나요?" 처럼 **줄거리를 아는 척하는 질문은 쓰지 않는다.** 책을 읽은 아이가 답할 수 있되, 질문 자체는 요약이 보장하는 사실 안에서만 말한다.

- 좋음: "이 책에 나오는 날씨 중에 가장 좋아하는 건 뭐였나요?" (요약이 '날씨를 소개한다'고 말함)
- 나쁨: "주인공이 비 오는 날 무엇을 했나요?" (요약에 그런 말이 없다)

이것이 이 설계에서 품질을 지키는 유일한 장치다. 틀리면 아이가 책에 없는 것을 묻는 질문을 받는다.

**틀로 정해 둔 것 — 모든 책에 같다**

- 별점 다섯 칸
- 읽은 날
- 한 줄 감상
- 새로 안 낱말 (자유 입력)

## 자료 파일

질문은 **만들 때 한 번** 만들어 파일로 굳힌다. 브라우저에 키를 넣지 않고, 쓸 때마다 돈이 들지 않는다.

**쪼개는 방법: Book No. 앞 세 글자** — `S1624` → `act/S16.js`

54묶음, 평균 89권, 가장 큰 것이 269권이다. 아이가 책 하나를 열 때 받는 파일이 그만큼이라 휴대폰에서도 가볍다. 전부 한 파일로 두면 1.7MB 를 받아야 한다.

Book No. 로 쪼개므로 목록을 다시 만들어도 자리가 어긋나지 않는다(`catalog-sum.js` 는 순번을 쓰지만 이건 쓰지 않는다).

```js
// act/S16.js
window.ACT = window.ACT || {};
ACT["S1624"] = { s: "한 줄 요약", q: ["...", "...", "..."], h: ["", "", ""] };
```

`s` 는 한 줄 요약(`catalog-sum.js` 에서 그대로 옮겨 적는다 — 그래야 `read.html` 이 641KB 짜리 요약 파일을 받지 않아도 된다), `q` 는 질문, `h` 는 한국어 도움말이다. 1벌은 질문이 이미 한국어라 `h` 가 빈 문자열이다.

## 화면

**`read.html?no=S1624`** — 새 화면 하나.

- 위: 표지·제목·저자·AR·렉사일·갈래·주제·수상·한 줄 요약 (서재 상세와 같은 정보)
- 가운데: 별점 / 질문 3개와 답하는 칸 / 한 줄 감상 / 새로 안 낱말
- 아래: 저장. 다시 열면 적은 것이 그대로 있다

받는 파일: `config.js` → `store.js` → `catalog.js` → `act/<앞세글자>.js`. 첫 줄은 `RB.gate()`.

`catalog-sum.js`(641KB)는 **받지 않는다.** 한 줄 요약은 질문을 만들 때 이미 썼고, 화면에 띄울 요약은 활동 파일에 함께 적어 둔다.

**저장 키:** `rbact:<이름>` — 지금 쓰는 `rbflu:` `rbar:` 와 같은 방식이다.

```js
{ "S1624": { star: 4, date: "2026-09-21", a: ["", "", ""], note: "", words: "" } }
```

**서재에서 가는 길:** 상세 패널의 [학습하기] 옆에 **[읽고 나서 →]** 를 둔다. 학습 콘텐츠가 있는 11권에는 단추가 둘, 나머지 4,809권에는 [읽고 나서] 하나가 뜬다.

## 만드는 방법

**API 키를 쓰지 않는다.** 이 컴퓨터에 Anthropic 키가 없고, 원장님이 따로 발급받거나 결제하실 일도 없다.

서브에이전트를 54묶음에 나눠 보낸다. 각 서브에이전트는 자기 묶음의 책들을 받아 `act/<앞세글자>.js` 파일 **하나를 직접 쓴다.** 결과를 나에게 돌려주지 않는다 — 4,820권의 질문이 대화에 쌓이면 안 된다.

**먼저 30권.** 세 벌에서 열 권씩 뽑아 만들어 원장님께 보여 드린다. 승인 전에는 나머지를 돌리지 않는다.

중간에 끊겨도 만든 파일은 남는다. 이미 있는 묶음은 건너뛰고 이어서 돌린다.

## 재사용하는 것

- `app.css` 의 `.top`·`.box`·`.btn`·`.row`
- 이름칸 `#who` 와 `rb1:who` 키
- `library.html` 의 표지·책등 그림 만드는 법
- `config.js → store.js` 순서와 `RB.gate()`

`vercel.json`·`store.js`·`report.js`·`app.css` 는 손대지 않는다.

## 검증

- `node scripts/check-act.js` — 묶음 파일들이 4,820권을 빠짐없이 덮는가, 질문이 3개씩 있는가, 빈 문자열이 없는가
- `read.html#selftest` — 벌 셈하기, 저장·불러오기
- `npm test` 에 연결
- 옛 브라우저(카카오톡 안 브라우저) 문법 검사: `?.` `??` `(?<` 없음

## 하지 않는 것

- 4,820권의 9단계 학습 (책 본문이 없다)
- 낱말 소리 (4만 8천 개, 약 8GB)
- 종이로 뽑기 (이번에는 화면만)
- 선생님이 답을 보는 화면 (아이 기기에만 저장된다. Supabase 가 붙으면 그때)
