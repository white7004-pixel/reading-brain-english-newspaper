# 에듀냅 스튜디오 업그레이드 설계 (영상 다양화 + 설명멘트)

- 작성일: 2026-10-05
- 상태: 초안 (검토 대기)
- 대상: `dolai1863/edunap` 의 스튜디오(영상비서). 이 문서는 읽기 전용으로 코드를 확인하고 쓴 설계서이며, 에듀냅 저장소에는 아무것도 쓰지 않았다.
- 앞선 문서 `2026-10-05-shorts-maker-design.md`(독립 서비스 가정)를 에듀냅 현실에 맞춰 대체한다. 레시피 메뉴판과 비용 최소화 원칙은 이 문서가 이어받는다.

## 1. 목적과 범위

원장님이 **사진 + 사진 설명 + 원하는 방향**만 적으면 쇼츠/영상이 나오게 하고, 영상마다 **게시용 설명멘트**(인스타, 당근 등)를 함께 써준다.
영상의 **화면 크기와 길이**는 원장님이 정한다.

**범위 안:** 영상 스타일 다양화, 사진 설명 반영, 화면 크기·길이 자유 입력, 설명멘트 자동 작성, 저비용 모드.
**범위 밖:** 인스타·유튜브·네이버·카카오로의 직접 게시(API 연동), 예약 게시. 원장님이 영상을 받아 직접 올린다.

## 2. 현재 스튜디오 (코드로 확인한 사실)

| 항목 | 현재 |
|---|---|
| 흐름 | 프롬프트 → Claude 대본(`src/lib/studio/script-gen.ts`) → 대본 확인 → TTS(ElevenLabs)·삽화(gpt-image) 생성 → 삽화 확인 → Lambda 렌더 → 완성 mp4 |
| 상태 | `VideoProject` 모델, 상태 머신(`state.ts`): DRAFT → SCRIPT_READY → ASSETS_GENERATING → ASSETS_READY → RENDERING → DONE / FAILED |
| 형식 | `shorts916`(1080×1920), `explain169`(1920×1080) 두 가지. 길이 선택 30·60·90초(가로 60~180초) (`types.ts`의 `TARGET_CHOICES`) |
| 대본 길이 | 목표 초수에서 글자 수와 장면 수를 역산(`deriveSceneBounds`, 유효 5.3자/초) |
| 템플릿 | 8종(`templates.ts`): 모집, 설명회, 마감, 개념 요약, 강의형, 공지, 상담 안내, 다짐. 프롬프트 지침(scaffold) 방식 |
| 사진 업로드 | 사진·영상을 장면에 배정 가능(`mediaIndex`), 사진은 확대 이동. 업로드 정보에는 **설명 칸이 없다**(`UploadedMedia`) |
| 비용 | 편당 원가 기록(`cost.ts`). 삽화 1장 약 $0.19로 가장 큼. 월 10편 상한(`access.ts`), 올인원 구독 전용 |
| 렌더 | `video-service/remotion`(Remotion) + `video-service/scene-lambda`(화이트보드 장면 렌더). 합성 props 계약은 zod 스키마 |
| 게시 | 게시 기능 없음 |

참고로 블로그 자동화는 이미 영상을 네이버 블로그 임시저장함에 넣을 수 있으나, 이번 범위에서는 쓰지 않는다.

## 3. 빈틈

1. 대본 생성이 사진 내용을 모른다. 사진은 대본이 나온 뒤에 사람이 장면에 붙인다.
2. 화면 크기와 길이가 고정이다.
3. 영상 종류가 화이트보드 한 가지다. 사진 중심 영상도 삽화 생성 비용을 쓴다.
4. 게시용 설명 문구가 없다.

## 4. 설계

원칙: **기존 상태 머신, 게이트, 원가 기록, 접근 제어를 유지하고 확장한다.** 새 필드는 모두 선택값으로 추가해 기존 프로젝트가 그대로 동작하게 한다.

### 4.1 영상 스타일 축
`VideoProject.style`(기본 `whiteboard`)을 추가한다.

| style | 내용 | 삽화 생성 | 단계 |
|---|---|---|---|
| `whiteboard` | 기존 | 함 | 기존 |
| `photo-story` | 사진 + 자막 + 내레이션 (확대 이동) | **생략** | 1단계 |
| `text-punch` | 글자 위주 문장 3~5개 | 생략 | 2단계 |
| `quiz` | 문제 → 카운트다운 → 정답 | 생략 | 2단계 |
| `review-card` | 학부모 후기 카드 (동의 필요) | 생략 | 2단계 |
| `comic` | 학원 캐릭터 만화 (컷 아트 필요) | 생략 | 3단계 |
| `director-talk` | 원장님 사진 + 목소리 (음성 동의 필요) | 생략 | 3단계 |

기존 `templates.ts`의 8종은 목적(agent × purpose) 축으로 유지하고, 스타일은 별도 선택으로 둔다. 템플릿마다 추천 스타일을 지정한다.

### 4.2 입력 (사진 + 설명 + 방향 + 화면 설정)
- `UploadedMedia`에 선택 필드 `caption`(사진 한 줄 설명)을 추가한다. 예: "5학년 에세이 쓰기 수업".
- 방향은 기존 `prompt`를 그대로 쓴다.
- 화면 설정: `aspect`(9:16 / 4:5 / 1:1 / 16:9 / 직접 입력 가로·세로 px)와 `targetSec`(자유 입력, 상한은 쇼츠 90초·가로 180초 유지).
- 대본 생성기가 사진 설명을 받아 **장면에 사진을 직접 배정**한다(`mediaIndex`를 AI가 채움). 원장님은 게이트1에서 고칠 수 있다.
- 설명이 비어 있는 사진은 그대로 허용하되, 어디에 쓸지는 원장님이 정한다. 사진 자체를 AI에게 보여주는 방식은 비용이 늘어 기본값으로 두지 않는다(7장 결정 대상).

### 4.3 화면 크기·길이 가변
- Remotion 컴포지션을 폭·높이를 props로 받는 하나의 틀로 일반화한다(`calculateMetadata`가 이미 길이를 계산한다).
- 글자 크기와 안전영역은 화면 크기에 비례해 계산한다. 사진 비율이 맞지 않으면 흐린 배경 채움을 기본으로 한다.
- 대본 길이 역산은 기존 `deriveSceneBounds`를 유지한다. 장면 수 상한(8)과 장면당 140자 제한은 그대로다.

### 4.4 저비용 모드
- **삽화 생략:** `style != whiteboard`이면 삽화 생성 단계를 건너뛴다. 편당 원가에서 가장 큰 항목이 사라진다. 게이트2는 음성 확인만 남는다.
- **목소리 선택:** `ko_female`, `ko_male`에 `none`(자막만)을 추가한다. `none`이면 TTS를 건너뛰고, 자막 타이밍은 글자 수(약 5.3자/초)로 계산한다.
- **한도:** 월 10편 상한은 실비 때문에 걸린 것이다. 삽화·TTS가 없는 모드는 실비가 작으므로 모드별 한도를 나누는 안을 7장에서 결정한다.
- 원가 기록(`logCost`)은 새 경로에도 동일하게 남긴다.

### 4.5 설명멘트 자동 작성
영상마다 채널별 설명 문구를 만든다.

- **생성 시점:** 게이트1(대본 확정) 직후에 글자만으로 만든다. 음성·삽화 비용이 들지 않는다. 완성 화면에서 보고 고친다.
- **저장:** `VideoProject.captions`(JSON, 선택). 구조는 채널별로 `{ 본문, 해시태그? , 제목? }`이다.
- **입력:** 확정된 대본, 학원 브랜딩(이름·문의처), 선택 입력(지역, 상담·신청 링크, 꼭 넣을 문구).
- **채널 형식(초안, 당근·유튜브 서식은 구현 전에 확인):**
  - 인스타: 첫 줄 훅 → 본문 3~5줄 → 행동 유도 → 해시태그 5~10개
  - 당근: 동네 이웃에게 말하듯 친근한 톤, 학원 소개·위치·문의 방법 중심, 해시태그 최소화
  - 유튜브 쇼츠: 제목(짧게) + 설명 + 해시태그 몇 개
  - 블로그·카톡 공지: 정중한 안내문 한 편
- **안전 규칙:** 입력에 없는 수치·성과를 지어내지 않는다. 최상급·합격 보장 같은 과장 표현은 쓰지 않고, 생성 후 금지어 목록으로 한 번 더 검사해 경고한다(기존 대본 프롬프트 규칙과 동일 정신).
- **UI:** 완성 화면에 채널별 탭, **복사 버튼**, 수정 가능한 입력창을 둔다. 영상은 "받기" 버튼과 휴대폰 공유 버튼으로 넘긴다.

### 4.6 UI 변경
- `PromptStep`: 영상 스타일 선택, 사진별 설명 입력, 화면 크기·길이 입력.
- `ScriptStep`: 장면에 배정된 사진 확인과 교체.
- 완성 단계(`RenderStep` 이후): 설명멘트 패널.

### 4.7 안전과 동의
- 학생 얼굴이 나오는 사진에는 얼굴 가림 옵션(이모지 또는 흐림)을 제공한다.
- 후기 카드, 원장님 목소리, 사진 사용에는 동의 체크를 둔다.
- 대본과 설명멘트의 과장 표현 검사는 4.5와 동일하다.

## 5. 단계별 계획

| 단계 | 내용 |
|---|---|
| 1단계 | `photo-story` 스타일, 사진 설명, 화면 크기·길이 자유 입력, 삽화 생략, 목소리 `none`, **설명멘트 패널** |
| 2단계 | `text-punch`, `quiz`, `review-card` 스타일과 템플릿 추가 |
| 3단계 | `comic`(학원 캐릭터), `director-talk` |

3단계의 `comic`은 이 저장소의 `reels/src/comic`을 `video-service/remotion`으로 옮겨 붙이는 방식이다. 다만 이 저장소의 음성·믹스는 Python 스크립트(`audio/episode.py`)이므로 에듀냅의 TS 파이프라인(ElevenLabs, Remotion의 볼륨 제어)으로 다시 구현해야 한다.

## 6. 검증
- 길이: 목표 초수와 ±1프레임.
- 비율: 4가지 비율의 정지컷에서 자막이 안전영역을 넘지 않는지 확인.
- 설명멘트: 응답 JSON 구조 검증, 금지어 검사 테스트. 레포 관례인 `node --test`/`tsx` 방식으로 작성.
- 기존 프로젝트: `style` 미설정 프로젝트가 이전과 똑같이 동작하는지 회귀 확인.
- 정적 검사: `npm run typecheck`, `npm run lint`.

## 7. 결정이 필요한 것
1. **Remotion 라이선스.** 에듀냅은 이미 Remotion Lambda를 쓴다. 서비스형 자동 렌더에 해당하는 조건을 충족하는지 확인이 필요하다. 공식 약관은 읽지 못했다.
2. **월 한도 정책.** 삽화·TTS가 없는 모드를 별도 한도로 나눌지.
3. **사진을 AI에게 직접 보여줄지.** 설명 입력이 번거로울 때의 대안이지만 호출 비용이 늘어난다.
4. **당근·유튜브 설명 서식.** 실제 입력창 구조를 확인해 형식을 확정한다.
5. **학원 지역·링크 정보의 저장 위치.** 현재 브랜딩 정보(`branding.ts`)에 지역 필드가 있는지 확인하고 필요하면 추가한다.
6. **동의 문구.** 학생 얼굴, 후기, 음성 사용에 대한 문구와 저장 방식.
