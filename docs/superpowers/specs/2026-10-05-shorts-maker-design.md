# 학원 쇼츠 메이커 설계 (에듀냅 연동용)

- 작성일: 2026-10-05
- 상태: 초안 (검토 대기)
- 관련 코드: `reels/` (Remotion 프로토타입), `reels/episodes/` (스펙 계약 초안)

## 1. 목적과 범위

원장님이 **사진 + 사진 설명 + 원하는 방향 한두 문장**만 적으면 쇼츠/동영상이 만들어지는 기능을 에듀냅에 붙인다.
영상의 **가로·세로 크기와 길이(초)** 는 원장님이 정한다.

1차 산출물은 **영상 레시피 메뉴판과 우선순위**다. 우선순위의 기준은 **원장님이 쉽게 만드는 것**(입력이 적고 실패 가능성이 낮은 것)이다.

범위 밖: 에듀냅 본체 코드 수정(저장소·스택 미확인), 결제·요금제, 유행 음원 앱 내 삽입(불가).

## 2. 사용자 흐름

1. 원장님이 사진을 올리고 사진마다 한 줄 설명을 단다.
2. 원하는 방향을 한두 문장으로 쓴다. (예: "독해력이 걱정인 학부모에게 우리 수업이 다르다는 걸 보여주고 싶어요.")
3. 화면 설정을 고른다: 비율(9:16 / 4:5 / 1:1 / 16:9 / 직접 입력), 길이(15·30·45·60초 / 직접 입력, 최대 90초), 목소리, 음악.
4. AI가 만든 **대본 미리보기를 1회 확인**한다. 장면별 정지컷과 자막·대사가 보이며, 대사를 고칠 수 있다.
5. 렌더 버튼을 누르면 결과물 3종이 나온다: 완성 mp4, VOICEONLY mp4(앱에서 유행곡을 얹는 용), 썸네일.

확인 없이 바로 생성하는 모드는 만들지 않는다. 학원 이름으로 나가는 문구이므로 확인 1회를 기본으로 한다.

## 3. 영상 레시피 메뉴판 (14종)

별이 많을수록 원장님 입력이 적다.

| # | 레시피 | 원장님이 넣는 것 | 쉬움 | 현재 상태 |
|---|---|---|---|---|
| 1 | 학부모 고민 → 해법 | 사진 3~4장, 문구 몇 줄 | ★★★ | 있음 (`reels/`) |
| 2 | 학생 결과물 쇼케이스 | 작품 사진 3~5장 | ★★★ | 있음 (Evidence 씬) |
| 3 | Q&A 쇼츠 | 학부모 질문 1개 | ★★★ | 있음 (HyperFrames 버전) |
| 4 | 공지·이벤트 카드 | 포스터 또는 일정 | ★★★ | 있음 (HyperFrames 버전) |
| 5 | 수업 현장 스케치 | 수업 사진 | ★★★ | 1번 변형 |
| 6 | 글자 위주 릴스 | 문장 3~5개 | ★★★ | 신규, 단순 |
| 7 | 퀴즈 챌린지 | 문제·정답 | ★★★ | 신규 |
| 8 | 표현 리스트형 | 표현 목록 | ★★★ | 신규, 단순 |
| 9 | 학부모 후기 카드 | 후기 문장 (동의 필요) | ★★☆ | 신규 |
| 10 | 문법 만화 | 대사 | ★★☆ | 있음 (`reels/src/comic`) |
| 11 | 원장님 한마디 | 사진 1장, 녹음 또는 TTS (음성 동의 필요) | ★★☆ | 신규 |
| 12 | 성장 Before/After | 사진·점수 (학생 동의 필요) | ★☆☆ | 신규 |
| 13 | 학원 마스코트 일상툰 | 캐릭터 아트 | ★☆☆ | 아트 의존 |
| 14 | 월간 시리즈 패키지 | 위 레시피 묶음 | – | 2차 |

**경우의 수:** 레시피 14 × 목소리 3(AI 캐릭터 / 원장 녹음 / 자막만) × 음악 3(오리지널 / 음성만 내보내기 / 무음) × 길이 3(15·30·45초) = 378가지.
원장님이 실제로 고르는 것은 레시피 하나와 토글 3개다. 비율은 별도 입력이다.

### 우선순위
1. **1단계:** 1~5번. 기존 자산을 재활용하고 입력이 가장 적다.
2. **2단계:** 6~10번. 새 템플릿이 필요하고, 만화는 컷 아트 라이브러리가 필요하다.
3. **3단계:** 11~13번. 음성 동의, 학생 개인정보, 마스코트 아트가 먼저 정리돼야 한다.

## 4. 구조

각 단위는 하나의 역할만 하고, 약속된 입력과 출력으로만 연결된다.

| 단위 | 역할 | 입력 → 출력 | 상태 |
|---|---|---|---|
| 요청 스키마 | 원장님 입력을 한 덩어리로 정의 | 사진[{설명, 중심점?}], 방향, 형식(가로·세로·초수·fps), 목소리, 음악 | 신규 |
| 학원 프로필 | 학원별 고정값 | 이름, 로고, 색, CTA, 캐릭터와 목소리, 금지 문구 | 있음 (`academy`, `cast`) |
| 기획기 (AI) | 스토리보드 생성 | 요청 → 스토리보드 JSON (스키마 검증) | 신규 |
| 목소리 어댑터 | 대사를 음성으로 | 텍스트, 목소리 → wav (공급자 교체 가능) | 있음 (HeyGen) |
| 길이 맞춤기 | 음성 길이를 재서 정확히 N초로 | 스토리보드, 음성 → 타임라인 | 일반화 필요 |
| 믹서 | 음악, 더킹, -14 LUFS | 타임라인 → 완성 음원, VOICEONLY 음원 | 있음 (`audio/episode.py`) |
| 렌더러 (가벼운 엔진) | 단순 레시피(1·2·4·5·6·8번)를 ffmpeg로 합성 | 타임라인, 가로, 세로 → mp4 | 시험 렌더 완료, 구현 필요 |
| 렌더러 (풍부한 엔진) | 만화 등 복잡한 연출을 Remotion으로 렌더 | 타임라인, 가로, 세로 → mp4 | 세로 고정, 가변화 필요 |
| 미리보기 | 장면별 정지컷과 대사 목록 | 스토리보드 → 이미지들 | 신규 |
| 작업 큐·저장 | 대기열, 상태, 파일 보관, 사용량 한도 | – | 에듀냅 확인 후 결정 |

### 데이터 흐름
요청 → 기획기 → **스토리보드 미리보기 (원장님 확인 1회)** → 목소리 → 길이 맞춤 → 믹서 → 렌더러 → 결과물 3종.

### 가변 형식 대응
- 현재 템플릿은 1080×1920에 길이가 고정이다. 가로·세로·초수를 입력값으로 받는 영상 틀로 일반화한다.
- 글자 크기와 안전영역은 화면 크기에 비례해 계산한다. (세로 기준 위 220px, 아래 320px을 비율로 환산)
- 사진 비율이 맞지 않으면 중심이 잘리지 않도록 흐린 배경 채움을 기본으로 한다.
- 계약은 `요청 → 스토리보드 → 타임라인`이고, 렌더러는 교체 가능한 부품이다. 레시피마다 두 엔진 중 하나를 지정한다(8장). Remotion은 에듀냅에 붙이기 전에 라이선스를 확인해 확정한다.

### 길이 맞춤 규칙
- 목표 초수에서 내레이션 글자 수를 역산한다. 이번 작업 측정치로 한국어 약 6글자/초이며, 30초면 150자 안팎이다.
- 음성 생성 후 실제 길이를 재서 사진 노출 시간을 조정한다. 길면 속도를 올리고, 그래도 넘으면 기획기에 문장 축소를 요청한다(최대 2회).
- 결과 길이는 목표와 ±1프레임 이내여야 한다.

## 5. 오류 처리
- **사진이 너무 적음:** 확대·이동 컷으로 분할하거나 더 짧은 길이를 제안한다. 억지로 늘리지 않는다.
- **음성이 길이를 넘김:** 속도 상향 → 문장 축소 요청 → 실패 시 사유와 함께 알린다.
- **TTS·렌더 실패:** 1회 재시도 후 실패로 표시하고 사유를 보여준다. 크레딧 소진은 별도 경고한다.
- **안전장치:** 학생 얼굴 처리 옵션, 과장 문구("상위 1%", "100% 합격" 등) 경고와 수정 제안, 음성·사진 사용 동의 체크가 없으면 렌더를 막는다.

## 6. 검증
- 길이: 목표 초수와 ±1프레임.
- 비율: 4가지 비율에서 정지컷을 뽑아 자막이 안전영역을 넘지 않는지 확인.
- 음량: -14 LUFS ±1, 목소리가 음악보다 +9dB 이상 큼 (`audio/episode.py`가 이미 측정 출력).
- 통합: 사진 5장으로 30초 쇼츠를 끝까지 생성.

## 7. 확정되지 않은 것 (진행 전 결정 필요)
1. **에듀냅의 스택·저장소·인증.** 이 저장소는 영어신문 앱이라 에듀냅 코드가 없다.
2. **렌더 엔진 라이선스.** Remotion은 4인 이상 회사나 SaaS 자동화에 유료 조건이 있을 수 있고, 공식 약관은 아직 읽지 못했다. HyperFrames는 Apache 2.0이다. ffmpeg는 사용할 빌드의 라이선스를 확인한다. 가벼운 엔진을 쓰면 Remotion 의존이 줄어든다.
3. **음성 공급자 약관과 비용.** 여러 학원이 쓰는 서비스에서 HeyGen API를 쓸 수 있는지, 영상 한 편당 비용이 얼마인지 측정이 필요하다.
4. **이미지 권리.** 만화 컷과 마스코트의 출처와 상업 이용 조건.
5. **동의 절차.** 원장님 목소리, 학생 얼굴, 학부모 후기.
6. **렌더 시간.** 이번 환경에서 42초 영상 렌더가 수 분 걸렸다. 동시 요청 처리와 대기 시간 기준을 정해야 한다.

## 8. 비용 최소화 구조

돈이 드는 곳은 **목소리(TTS), 대본(AI), 렌더** 3곳이다. 음악은 직접 합성하고 사진은 원장님 것을 쓰므로 0원이다. 아래 수치와 무료 한도는 제가 확인한 것과 그렇지 않은 것을 구분해 적는다.

### 8.1 렌더러를 두 갈래로 나눈다
| 엔진 | 쓰는 레시피 | 특징 |
|---|---|---|
| 가벼운 엔진 (ffmpeg) | 1·2·4·5·6·8번 (사진, 글자, 카드 중심) | 시험 결과: 사진 4장, 확대 효과, 자막 박스, 음성을 합친 1080×1920 영상이 4코어 서버에서 **약 23초**. 표현은 단순하다. |
| 풍부한 엔진 (Remotion) | 10번 만화 등 복잡한 연출 | 표현이 풍부하지만 렌더가 느리다. 만화 영상은 정확히 재지는 않았으나 수 분 걸렸다. |

- ffmpeg는 빌드에 따라 GPL/LGPL 조건이 달라지므로 서비스에 넣기 전에 사용할 빌드의 라이선스를 확인한다.
- 이 시험은 길이 제어가 거칠었다(결과 26.7초). 정확한 길이 맞춤은 구현 단계에서 처리한다.

### 8.2 목소리는 3단계로 나눈다
| 단계 | 방법 | 비용 |
|---|---|---|
| 0원 모드 | 자막과 오리지널 음악만 | 0원 |
| 저비용 | 원장님 직접 녹음, 인스타 앱 글자 읽어주기, 무료 등급 TTS | 0원 또는 무료 한도 |
| 프리미엄 | HeyGen 음성 | 크레딧 사용 |

- **원장님 녹음(대본 읽어주기 모드):** 화면에 대사가 한 줄씩 나오고, 원장님이 읽으면 무음 구간을 자동으로 잘라 붙인다. 원장님 한마디(11번)도 같은 기능을 쓴다.
- **인스타 앱 읽어주기:** 우리는 무음 영상과 자막 타이밍을 만들고 목소리는 앱 기능에 맡긴다. 앱 음성 길이가 어긋날 수 있어 장면마다 여유를 둔다. 해당 기능의 현재 제공 여부와 조건은 확인하지 못했다.
- **무료 등급 TTS 후보:** Google Cloud TTS, Azure Speech, MeloTTS(오픈소스, 한국어 지원). 한도와 약관은 바뀔 수 있어 도입 전에 확인한다. 음질은 아직 들어보지 못했다.
- **제외:** 비공식 방식으로 Microsoft 음성을 가져오는 도구는 약관 위험이 있어 쓰지 않는다.

### 8.3 크레딧이 새지 않게 하는 장치
- **미리보기는 글자만 보여준다.** 음성은 원장님이 "렌더"를 누른 뒤에만 만든다. 대본을 고치다 버려도 TTS 비용이 없다.
- **문장 단위로 저장해 재사용한다.** 같은 문장은 한 번만 만든다(`audio/episode.py`에 구현됨).
- **공용 문장은행:** "프로필 링크에서 레벨 테스트 신청" 같은 자주 쓰는 문장은 전 학원이 공유하는 음성으로 한 번만 만든다. 학원 이름만 학원별로 한 번 만든다.
- **학원별 월 한도:** 무료 모드는 넉넉히, 프리미엄은 횟수를 제한한다.
- **대본 AI:** 레시피 대부분은 빈칸 채우기 템플릿이라 AI 없이도 된다. AI는 "방향 한 줄 → 문구 다듬기"에만 쓰고 작은 모델을 쓴다. 호출당 비용은 요금표로 확인한다.
- **서버:** 작은 서버에서 요청을 하나씩 처리하고, 기본 해상도는 720×1280, 1080은 선택으로 둔다. 시범 단계의 무료 실행 환경은 약관상 운영용으로 맞지 않을 수 있어 쓰지 않는다. 원장님 PC에서 렌더하는 방식은 설치가 번거로워 제외한다.

### 8.4 추천 조합
가벼운 엔진 + 원장님 녹음 또는 인스타 읽어주기 + 공용 문장은행. 이렇게 하면 1단계 레시피 대부분이 서버 비용과 TTS 비용을 거의 쓰지 않는다.
