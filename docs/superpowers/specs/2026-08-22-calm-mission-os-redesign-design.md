# Monggle Calm Mission OS Redesign

## Goal

몽글을 카드가 나열된 웹 프로토타입에서, 사용자가 지금 해야 할 한 가지를 즉시 이해하고 실행할 수 있는 전문적인 Android 집중 관리 앱으로 재설계한다.

## Product Direction

디자인 원칙은 `Todoist의 절제된 정보 구조 + Tiimo/Structured의 시각적 시간 표현 + Finch의 선택적 정서 보상`이다. 캐릭터와 보라색은 브랜드를 만드는 보조 계층이며, 핵심 행동과 정보를 가리거나 화면을 장식하기 위해 사용하지 않는다.

## Scope

이번 단계는 기존 기능과 저장 데이터를 유지한 채 다음 화면 계층을 개편한다.

- 오늘 화면: 현재 할 일 하나를 최우선으로 배치하고 입력, 우선순위, 하루 흐름은 점진적으로 공개한다.
- 앱 셸: 중복 사용자 유형 선택기를 제거하고 간결한 브랜드/날짜 헤더를 제공한다.
- 하단 내비게이션: 아이콘과 라벨을 함께 사용하는 네 개의 목적 중심 탭으로 단순화한다.
- 설정 화면: 거대한 폼 카드 대신 프로필, 집중, 화면, 연결의 그룹형 설정 행으로 구성한다.
- 캐릭터: 콘텐츠 위에 떠 있는 장식을 제거하고 현재 과제·완료·빈 상태에서만 작은 코치로 사용한다.
- 디자인 시스템: 표면, 타이포그래피, 간격, 색상, 그림자, 포커스 및 모션 규칙을 통일한다.

백엔드 저장소, 일정 계산, 메시지 연결, 루틴 및 집중 세션의 비즈니스 로직은 변경하지 않는다.

## Information Architecture

하단 탭은 다음 네 개로 정의한다.

1. `오늘`: 지금 할 일, 다음 일정, 빠른 입력, 오늘의 흐름
2. `계획`: 기존 루틴과 할 일 계획 기능을 모은 진입점
3. `집중`: 현재 과제와 집중 타이머
4. `나`: 메시지 연결, 프로필, 환경설정 및 외부 서비스 연결

기존 `메시지`와 `설정` 기능은 삭제하지 않는다. `나` 화면의 그룹형 행을 통해 동일한 기능으로 이동한다. 기존 URL이 있다면 호환성을 유지한다.

## Today Screen

화면의 첫 뷰포트에는 다음 순서만 노출한다.

1. 날짜와 짧은 환영 문구
2. 컴팩트한 에너지 선택기
3. `지금 할 일` 카드와 단일 주요 행동 `집중 시작`
4. 다음 일정 최대 두 개
5. 빠른 입력 진입 버튼

전체 빠른 입력 폼, 우선순위 목록, 마스터 목표, 상세 타임라인은 첫 화면 아래 또는 사용자가 펼친 뒤 표시한다. 할 일이 없을 때는 과장된 빈 카드 대신 짧은 안내와 `할 일 추가` 행동을 보여준다.

## Navigation and Shell

- 상단 사용자 유형 선택기는 제거하고 사용자 유형은 `나 > 프로필`에서만 변경한다.
- 하단 내비게이션은 아이콘과 라벨을 함께 사용하며 터치 영역은 최소 48px이다.
- 내비게이션과 콘텐츠 사이에 하단 safe-area 및 충분한 스크롤 여백을 둔다.
- 고정 내비게이션, 현재 과제 표시, 캐릭터가 서로 또는 콘텐츠와 겹치지 않아야 한다.
- 현재 탭은 색상, 아이콘 상태, 배경 컨테이너로 명확히 구분하고 색상만으로 상태를 전달하지 않는다.

## Settings

설정은 다음 네 그룹으로 표시한다.

- 프로필: 사용자 유형
- 집중 환경: 기본 집중 시간, 휴식 시간, 카메라 집중 감지
- 화면: 테마, 배경 사진
- 연결: Google Calendar, 메시지 연결, 카테고리 관리

각 행은 제목, 보조 설명 또는 현재 값, 필요한 경우 토글/화살표로 구성한다. 고급 편집 UI는 행을 선택했을 때 펼치거나 하위 패널에서 제공한다.

## Visual System

- 기본 배경은 밝은 중립색이고 보라색은 선택, 진행, 주요 행동에 제한한다.
- 화면 좌우 여백은 모바일 기준 16px, 주요 카드 안쪽 여백은 16~20px로 한다.
- 기본 카드 반경은 16~20px이며 모든 카드에 큰 그림자를 사용하지 않는다.
- 화면 제목은 한 번만 28~32px, 섹션 제목은 20~22px, 카드 제목은 17~20px, 본문은 14~16px로 제한한다.
- 주요 버튼은 최소 높이 52px, 일반 터치 영역은 최소 48px이다.
- 캐릭터는 기본 64~80px이며 콘텐츠를 가리지 않는다.
- `prefers-reduced-motion`을 존중하고 전환 애니메이션은 200ms 내외로 제한한다.
- 텍스트와 배경은 WCAG AA 수준의 대비를 목표로 한다.

## Component Boundaries

- `AppShell`: 헤더, 라우트 콘텐츠 영역, safe-area와 전역 내비게이션만 책임진다.
- `BottomNav`: 탭 정의, 아이콘, 활성 상태와 접근 가능한 레이블만 책임진다.
- `TodayScreen`: 도메인 상태를 조합하고 섹션 순서를 결정한다.
- `NowTaskHero`: 현재 과제와 집중 시작 행동을 표시한다.
- `UpcomingPreview`: 다음 일정 최대 두 개와 상세 보기 진입을 표시한다.
- `SettingsScreen`: 설정 그룹을 조합한다.
- `SettingsRow`와 `SettingsSection`: 일관된 설정 행과 그룹 표현을 담당한다.

기존 도메인 컴포넌트는 가능한 한 유지하며 시각적 컨테이너와 노출 순서를 분리한다.

## States and Errors

- 현재 할 일 없음: 한 줄 안내와 할 일 추가 행동
- 다음 일정 없음: 빈 카드 대신 짧은 중립 텍스트
- 외부 연결 실패: 해당 연결 행 안에 상태와 재시도 행동 표시
- 로딩: 레이아웃 이동을 최소화하는 컴팩트 스켈레톤
- 오프라인: 기존 로컬 우선 동작을 유지하며 연결 기능에만 상태 표시

## Testing

- Vitest/Testing Library로 네 개 탭, 활성 상태, 접근성 레이블, 현재 할 일 우선 노출, 설정 그룹과 사용자 유형 중복 제거를 검증한다.
- 기존 저장소 및 도메인 테스트를 모두 실행해 데이터 동작이 유지되는지 확인한다.
- TypeScript 빌드와 Vite 프로덕션 빌드를 실행한다.
- Playwright로 360px, Pixel 7, 데스크톱 폭에서 핵심 화면을 캡처하고 겹침, 잘림, safe-area를 확인한다.
- 키보드 탐색, 포커스 표시, reduced-motion 및 기본 색상 대비를 수동 점검한다.

## Acceptance Criteria

- 첫 모바일 뷰포트에서 현재 할 일과 집중 시작 행동을 스크롤 없이 찾을 수 있다.
- 홈 헤더와 설정에 사용자 유형 선택기가 중복되지 않는다.
- 하단 내비게이션은 네 개 탭이며 각 탭에 아이콘, 텍스트 레이블, 활성 상태가 있다.
- 360px 이상 모바일 폭에서 캐릭터, 카드, 하단 내비게이션이 겹치지 않는다.
- 설정 기본 화면은 그룹형 행을 사용하며 큰 폼 입력이 한꺼번에 노출되지 않는다.
- 기존 핵심 기능과 저장 데이터가 유지되고 전체 테스트와 프로덕션 빌드가 통과한다.
